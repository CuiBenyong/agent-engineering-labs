# D27 实验：简历 v1 + 三个仓库 README

> 目标：把 `agent-service`、`mini-koda`、`mini-multi-agent` 三个学习项目变成简历上**经得起追问**的三条要点，并给三个仓库各补一份七段式 README。今天的产出是文档，不是程序——但每一个数字都必须是你自己跑出来的。

## 你会学到

- 用 STAR 一句话公式把三个项目各写成一条带数字的简历要点
- 给三个仓库分别补一份七段式 README，含 Mermaid 架构图
- 规划一段 3–5 分钟的项目 demo 视频
- 把中文简历翻译并润色成一版可以直接投的英文简历
- 用「诚信自检」通读一遍，确认没有夸大或没跑过的数字

## 目录

- `starter/`：四份挖空的模板，骨架和提示问句都写好了，待填处是 `> TODO：` 引用块
- `solution/`：填好的示范样例，用的是本课三个仓库的**真实实测数字**

两个目录里的文件名一一对应：

| 文件                 | 干什么用                                     |
| -------------------- | -------------------------------------------- |
| `star-bullets.md`    | 三条 STAR 要点的草稿纸，先在这里把数字定下来 |
| `readme-template.md` | 七段式 README 模板，复制到三个仓库各改一份   |
| `resume-cn.md`       | 中文简历，一页                               |
| `resume-en.md`       | 英文简历，一页                               |

**填的顺序是固定的**：`star-bullets.md` → `readme-template.md` → `resume-cn.md` → `resume-en.md`。先把数字和「放弃了什么」想清楚，简历只是把它们压缩成一行。

## 怎么用

这一天没有代码，所以**不需要** `pnpm install`、不需要 `MOCK=1`、也没有自检脚本。

1. 先跑数字。打开 `star-bullets.md` 列出的那几项自检，**真的跑一遍**，把输出抄下来：
   ```bash
   cd labs/agent-30days/day-07-agent-service-docker/solution && PORT=3907 MOCK=1 SELFTEST=1 pnpm start
   cd labs/agent-30days/day-10-sharding-lease/solution      && MOCK=1 SELFTEST=1 pnpm start
   cd labs/agent-30days/day-17-planner-executor-critic/solution && MOCK=1 SELFTEST=1 pnpm start
   ```
   X 和 Y 通常一个在 `starter/` 的输出里、一个在 `solution/` 的输出里。
2. 通读 `solution/` 的四份样例，看清楚「一个真数字被写成一行简历」长什么样。
3. 回到 `starter/`，把每个 `> TODO：` 换成**你自己的**内容。`solution/` 是参照物，不是答案。
4. 最后对着「验收标准」逐条自检。

## 验收标准

1. `starter/star-bullets.md` 三条 STAR 要点全部填完，每条都能指出「从 X 改善到 Y」里的 X 和 Y 分别来自哪个实验的哪一项自检输出，且每条都注明了测量条件。
2. 三份 README 七段齐全，快速开始都在三条命令之内；**在一个新建的空目录里照着自己写的敲一遍能跑起来**，跑不起来就改 README，不要口头补充。
3. 每份 README 的架构图是 Mermaid 源码、推到 GitHub 上确认真的渲染出来了、节点不超过 8 个；把图单独发给一个没做过 Agent 的后端，他能说出请求从哪进、活在哪干、状态存在哪。
4. 对着「关键设计决策」那三条各讲一遍，每条都说得出**放弃了什么**，全程不看稿、每条不超过 2 分钟。
5. `resume-en.md` 一页放得下、每条以动词开头、全文搜 `Responsible for` 零命中，不含照片、年龄、性别、婚姻状况与身份证信息，且三个项目都标了 `Personal project` 或 `Course project`。
6. 全文搜一遍自己写的所有数字，每一个都答得出「这是在什么条件下测的」。答不出的当场删掉。

## 常见坑

1. **写了没跑过的规模数字。** 「支撑百万 DAU」「QPS 5000」这种数出现在学习项目里，追问两句就穿帮——而且作废的不只是这一条，是你其余**全部**的真数字。宁可写「本地单机、MOCK 模式、2000 个模拟用户散到 256 个分片，最大桶 19 条」，朴素但每个字都站得住。
2. **把学习项目混进工作经历。** 三个项目必须在「项目经历」一栏并标注「个人项目 / 课程项目」。排版上也别让它看起来像某家公司的产出——这是诚信问题，不是格式问题。
3. **只有终值，没有对照。** 「最大桶 19 条」单看没有信息量，「2000 个用户散到 256 个分片，最大桶 19 条（理想 8）」才有。**X 和 Y 都要有**，只给 Y 等于没给。
4. **README 的「关键设计决策」写成了功能列表。** 「用了 Redis Streams」是功能，「用 Redis Streams 而不是 Kafka，放弃了跨机房复制和无限回溯，换来单机就能起」才是决策。这一段是整份 README 里唯一抄不来的部分，也是面试官挑追问的地方。
5. **英文简历是中文简历的机翻。** 中英差异不只是语言：英文版不放照片、年龄、性别、婚姻状况；每条动词开头；不写 `Responsible for`。机翻出来的句子在母语者眼里一眼可辨。
