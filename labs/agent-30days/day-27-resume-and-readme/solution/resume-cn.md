### 1. mini-multi-agent · 课程项目 · （起止月份）

多 Agent 编排服务：Planner–Executor–Critic 三角色，带共享工作区、工具预算与评审回路。仓库：（链接） · demo：（链接）

- 在「多个执行者并行写同一份图状态」的约束下，为了让共享工作区不出现同一子任务的多个版本，把 `workspace` 通道的 reducer 从数组追加换成按 id 原地更新，3 件并行子任务留下的记录从 **6 条（3 个重复 id，按 id 查到的是过期的 pending 版本）** 收敛到 **3 条（0 重复，查到 done 版本）**。（本地单进程、MOCK 模式、同一张图只换 reducer 做对照）
- 给每个子任务设 5 次工具调用上限、Critic 最多打回 2 次，预算耗尽时降级返回已有结果并标 `degraded`，而不是抛错中断整张图。
- 技术栈：TypeScript、LangGraph、PostgreSQL（自研 checkpointer）、JWT/JWKS 跨服务鉴权

### 2. mini-koda · 课程项目 · （起止月份）

Gateway 与 worker 池分离的 Agent 执行平台，消息总线解耦，同一用户消息严格保序。仓库：（链接） · demo：（链接）

- 在「worker 会被随时 kill、而同一用户的消息不能乱序」的约束下，给分片加了 `SET NX` + TTL 租约、把「校验持有者 + 续期」合成一个原子步、写入带 fencing token，使持有者假死后 **2.75 秒**由另一副本接手，接手前后同一用户的消息序号仍连续（`[1,2,3,4,5,6]`），旧持有者用过期代号续约与写入双双被拒。（本地单进程内起 2 个 worker、内存版基础设施、2000 个模拟用户散在 256 个分片上，最大桶 19 条；自检把生产口径 TTL 30s/续约 10s 等比压缩 10 倍）
- 按 token 建成本台账（金额冗余存不现算，因为单价会变而历史账单必须冻结），支持按用户与按天切分。
- 技术栈：TypeScript、Fastify、Redis Streams、PostgreSQL、Drizzle、Docker Compose

### 3. agent-service · 课程项目 · （起止月份）

把单个 Agent 封装成带流式输出与优雅停机的 HTTP 服务，一个容器起得来。仓库：（链接） · demo：（链接）

- 在「用户随时会关掉页面、而每个 token 都在计费」的约束下，在 SSE 推流循环里接上请求的中止信号并在每次 `yield` 前检查，把一次被中途放弃的会话的服务端生成量从 **103 个片段**降到 **6 个片段**（客户端读 5 个即断开，服务端只多生成 1 个便停止）。（本地单进程、MOCK 模式、单条约 103 字的模拟回复）
- 技术栈：TypeScript、Fastify、SSE、Docker
