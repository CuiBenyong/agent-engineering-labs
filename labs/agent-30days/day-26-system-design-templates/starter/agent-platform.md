# 模板一：Agent 平台

> 一句话主线（开口第一句就说）：**无状态执行 + 有状态编排。**
> Gateway 无状态水平扩，run 的状态落 Postgres，长任务靠消息总线解耦，编排在 worker。

时间盒：澄清 5' / 估算 3' / 草图 8' / 深入 15' / 权衡 5'。

---

## 1. 需求澄清（5 分钟）

五个通用问题，一个都不能省：

- 日活与并发会话数是多少？峰谷比大概多少？
- 单轮延迟预算是多少？首字要多快？必须流式吗？
- 成本预算是多少？按用户还是按租户结算？
- 是不是多租户？
- 失败可容忍度：一次执行失败，是重试、降级，还是必须成功？

这一题特有的三个问题：

- 单次执行大概多长？（三百毫秒别拆，三十秒必须拆）
- 工具有没有副作用？（有，则要人工确认档和参数上限）
- 需要主动推送吗？（需要，则多一个中心调度器）

> TODO：写下你会怎么应对「你先自己假设一个」——给出你的假设值和依据，一句话。

> TODO：写下这五个答案分别会把你的架构推向哪个方向（每条一句，说清「如果答案是 A 我就……」）。

## 2. 容量与成本估算（3 分钟）

价格口径：输入 0.15 美元 / 100 万 token，输出 0.60 美元 / 100 万 token。

单轮成本 = 输入 token ÷ 1000000 × 0.15 + 输出 token ÷ 1000000 × 0.60

> TODO：按你假设的日活、人均轮数、单轮 token 数，把下面五个数算出来，**并且把算式写下来**：
>
> - 单轮成本 = ？
> - 每天轮次 = ？
> - 每天 / 每月模型费 = ？
> - 峰值并发（利特尔法则：峰值 QPS × 单轮秒数）= ？
> - worker 副本数（并发 ÷ 单 worker 并发度）= ？
