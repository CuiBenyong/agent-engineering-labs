# D2 实验：手写 while 循环 Agent + 2 个工具

> 目标：不借助任何框架，用一个 for 循环 + 两个普通函数，做出一个会自己查天气、算差值、还能在工具报错后改对参数重来的 Agent——把昨天那张"思考 → 行动 → 观察"的动画变成有行号的代码。

## 你会学到

- 定义两个工具（查天气、计算器）的 JSON Schema
- 写一个 while 循环：调用模型 → 判断是否要工具 → 执行工具 → 把结果塞回 messages
- 故意让一个工具抛错，观察把错误信息回传给模型后它怎么应对
- 加一个最大循环次数保护，避免死循环

## 目录

- `starter/`：挖了 5 个练习的起始代码，`MOCK=1` 下可以直接跑
- `solution/`：参考答案

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env  # 填 OPENROUTER_API_KEY；没有 key 先用 MOCK=1
MOCK=1 pnpm start     # 离线模拟，走完整的四步循环
pnpm start            # 真模型
MOCK=1 pnpm start 演示死循环   # 假模型会一直请求同一个工具，用来验证步数上限拦得住
#                              #（英文版课程用的等价参数是 loop-forever）
```

> 说明：`starter/` 与 `solution/` 都不属于仓库根 pnpm workspace（根 `pnpm-workspace.yaml` 只包含
> `apps/*`），`pnpm install` 时要加 `--ignore-workspace`。

`MOCK=1` 下不需要任何 key：只有"调模型"这一个网络出口被打了桩（天气用的是内置数据表，不联网），
循环、工具执行、错误处理这些业务逻辑照常真跑。

模拟层是一个**演示级**的假模型：它靠数轮次和读观察结果来决定下一步，真实模型靠的是语义理解，
别把那段代码当生产做法。但它有两件事是真的——它真的会去读你回填的那些 role 为 tool 的消息
（读不到就会说自己没拿到数据），它第一次调计算器也真的会把单位写进表达式，只有当你把工具的
报错回传给它，它才会在下一轮改成纯数字。所以**"循环有没有写对"这件事，离线就能验**。

`starter/` 的 5 个练习点请**按 1 到 5 的顺序做，每做完一个都重跑一次**，你会看到症状一个接一个地变：

1. 补完 `calculate` 的 JSON Schema —— 不补，假模型不知道该传什么参数，只能空着手上。
2. 补完循环的分支判断 —— 不补，程序只调一次模型就收工，输出是"（模型这一轮没有说话）"。
3. 把工具结果回填成 `role: 'tool'` 消息 —— 不补，模型会说它没拿到两地的气温。
4. 把工具报错整理成一句话回传 —— 不补，模型一直用带单位的表达式重试，直到撞上步数上限。
5. 补上撞顶时给用户的那句交代 —— 不补，`演示死循环` 那条命令跑完只会给你一个空回复。

## 验收标准

1. `MOCK=1 pnpm start` 打印出四步循环轨迹，每一步都能看到这一步的停止原因，以及执行了哪些工具、拿回了什么结果。
2. 第 2 步能看到 `calculate` 因为参数带了单位而报错，第 3 步模型把参数改成纯数字后成功——这就是"错误回传让模型自纠错"的现场。
3. `MOCK=1 pnpm start 演示死循环` 会看到循环撞上步数上限被拦下，并给用户一句交代，而不是无限转下去或者返回空。
4. `starter/` 的五个练习点全部补完后，输出与 `solution/` 完全一致。
5. `pnpm typecheck` 通过，没有 `any`。

## 常见坑

- **漏掉模型那条 assistant 消息**：只把工具结果塞回 `messages`，却忘了先把带 `tool_calls` 的那条原样追加回去。
  历史里于是出现一条没有来由的工具返回，真模型会直接返回 400。本实验里 `messages.push(choice.message)`
  就在循环体的第二行，删掉它试一次，你会记得更牢。
- **把 `arguments` 当对象用**：它是一段 **JSON 文本**，必须 `JSON.parse` 一次；而且模型偶尔会吐出不合法的 JSON，
  所以这次解析本身也要被 `try` 住——`executeTool` 里的 `try` 是从解析那一行就开始的。
- **并行调用只回一条**：模型一次请求了杭州和北京两个城市的天气，你就要回**两条** `role: 'tool'` 消息，
  `tool_call_id` 逐个对上，少一条同样是 400。本实验第 1 步就是并行调用，正好拿来验。
- **把异常堆栈原样回传给模型**：堆栈里有文件路径和内部服务名，会原封不动进入下一次请求，还可能被模型
  复述给用户，而且动辄上千 token 每轮重发。`executeTool` 的做法是：堆栈只进日志（`console.error`），
  回给模型的只有你自己写的那一句话。
