# 虚构域名文本比较与独立核实

用纸笔或电子文档填写 `starter/answer.zh.md`，再对照 `solution/answer.zh.md`。练习只比较虚构主机名文字，不访问、点击、扫描或测试链接；不需要调用 AI、提供验证码或上传真实消息。

## 四个虚构字符串

`.example` 是为文档和示例保留的后缀。以下内容均为虚构文字，不对应真实机构或供访问的网站；A 只是纸面比较的对照，并非已核实的真实官方地址。

- A：`notice.example`
- B：`notice.example.other.example`
- C：`help.notice.example`
- D：`notlce.example`

假想消息催促读者打开链接处理事务并提供验证码；没有真实发送者、实际目标或机构答复。不要依据题设推断某个真实网址的归属或安全。

## 四步练习

1. 按点拆分 A 至 D；比较 B 在相似前缀之后还有什么，C 的结尾与 A 的文字关系，以及 D 的字母差异。
2. 将纸上可观察的拼写或层级，与实际发送者、目标、归属及安全等未知分开。
3. 审查假想错误判断：“B 含 A 所以同一家；C 是子域所以安全；D 一定诈骗；HTTPS 可证明安全。”说明哪些推断无法成立。
4. 写一条只用虚构字符串、禁止访问和判定安全的 AI 请求；再写本人已核实渠道、待询问事项和未核实状态。不提供验证码、密码或个人信息。

## 完成标准

B 是不同的完整名称，以 `other.example` 结尾；C 在文字层级上以点加 `notice.example` 结尾，但不因此证明可信；D 的第一段第四个字母与 A 不同。可见文字、实际目标、HTTPS、所有者及安全不可混为一谈；使用本人独立核实的渠道，不使用消息中的链接或号码。

## 官方延伸资料

- [IETF RFC 2606：保留的示例域名](https://www.rfc-editor.org/rfc/rfc2606.txt)：说明 `.example` 保留给文档示例。
- [FTC：如何识别和避免钓鱼信息](https://consumer.ftc.gov/articles/how-recognize-avoid-phishing-scams)：讨论通过已知的独立联系方式核实。
- [FTC：网上购物](https://consumer.ftc.gov/articles/online-shopping)：说明 HTTPS 加密本身不证明网站可信。

这些是公开资料入口，不是让你访问练习中的字符串或任何可疑链接。
