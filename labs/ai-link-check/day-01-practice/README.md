# Fictional hostname comparison and independent checks

Complete `starter/answer.md` on paper or in a document, then compare `solution/answer.md`. The exercise compares fictional hostname text only; do not visit, click, scan or test links. No AI call, verification code or real-message upload is required.

## Four fictional strings

`.example` is a suffix reserved for documentation and examples. These are fictional strings, not a real organization or websites to visit. A is only the paper comparison reference, not a verified real official address.

- A: `notice.example`
- B: `notice.example.other.example`
- C: `help.notice.example`
- D: `notlce.example`

An imaginary message urges the reader to open a link for a matter and provide a code. There is no real sender, actual destination or institutional response. Do not infer the ownership or safety of a real address from the scenario.

## Four steps

1. Split A through D at dots. Compare what follows B's similar prefix, C's ending relationship to A, and D's letter difference.
2. Separate spelling or hierarchy observable on paper from unknown actual sender, destination, ownership and safety.
3. Review an imaginary flawed verdict: “B contains A so it is the same organization; C is a subdomain so safe; D is definitely fraud; HTTPS proves safety.” Explain why the conclusions do not follow.
4. Write an AI request using only fictional strings that forbids visiting and safety verdicts. Then write a plan using a personally verified channel, questions to ask and an unverified status. Do not provide codes, passwords or personal information.

## Completion criteria

B is a different complete name ending in `other.example`. C's text ends in a dot followed by `notice.example`, but that does not prove trust. D's first label differs from A at the fourth character. Do not conflate visible text, actual destination, HTTPS, ownership and safety. Use a personally verified independent channel, not links or phone numbers in the message.

## Official further reading

- [IETF RFC 2606: Reserved Top Level DNS Names](https://www.rfc-editor.org/rfc/rfc2606.txt) explains that `.example` is reserved for documentation examples.
- [FTC: How to recognize and avoid phishing scams](https://consumer.ftc.gov/articles/how-recognize-avoid-phishing-scams) discusses verification using known independent contact details.
- [FTC: Online shopping](https://consumer.ftc.gov/articles/online-shopping) explains that HTTPS encryption alone does not establish a legitimate site.

These are public references, not instructions to visit the exercise strings or any suspicious link.
