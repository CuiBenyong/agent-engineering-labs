# D3 实验：把防御从提示词挪到结构上

同一批攻击用例（含 D2 那条绕过了检测器的自适应用例 A-10），四种方案对照。

## 跑起来

```bash
cd starter        # 或 solution
pnpm install --ignore-workspace
pnpm typecheck && pnpm start
```

离线运行，不需要模型也不需要网络。

> **starter 第一次跑出来是 ASR 0% / utility 0%。** 别高兴——那正是 D2 说过的那个反模式：
> **把 Agent 改成什么都不做，攻击成功率当然是 0。** 两个数字必须一起看。

## 这一天在做什么

核心原则（arXiv 2506.08837）：

> 一旦 Agent 摄入了不可信输入，就必须被约束到「那段输入不可能触发任何有后果的动作」。

落地成两句话：

1. **动作清单在看任何不可信内容之前就定死**（先定计划后执行）。
2. **读不可信内容的那次模型调用没有任何工具**，它的输出只能当数据用（隔离读取）。

注意这里**没有任何检测器、没有任何关键词表**。载荷写得多巧妙都不重要——
它想触发的动作压根不在计划里。

## 三个练习点

都在 `starter/src/agent/planned.ts` 里用 `TODO(N)` 标出来了。

1. **`plan()`：计划器。** 只看用户请求与预授权收件人。
   它的参数里没有工单正文，**你也不要把它加进来**——加进来这个模式就作废了。
2. **`quarantinedRead()`：隔离读取。** 调一次模型，把它想做的对外发送记下来，
   然后把所有动作丢掉，只返回一段字符串。
3. **`runPlanned()`：执行器。** 只把计划里的步骤变成动作。这一行就是那道墙。

## 验收标准

做完之后应该得到这张表：

```text
D2 第三档：聚光标注                40%   100%   达成      A-07 A-08 A-09 A-10
D2 第四档：标记加检测器            10%    83%   被丢弃    A-10
先定计划后执行                      0%   100%   被丢弃    （无）
  └─ 隔离模型被劫持 5 次，但它没有工具，一次都没发出去
先定计划后执行 加 预授权收件人      0%   100%   达成      （无）
```

## 手动验收清单

- [ ] **「隔离模型被劫持 5 次」这一行必须出现。** 它是本实验最重要的一句话：
      隔离模型**确实上当了**，它真的打算把客户名单发出去。它没能发出去，
      不是因为它没上当，是因为它手上没有那把钥匙。
      这和「我们的模型抗住了攻击」是两种完全不同的安全性。
- [ ] **看清楚代价那一列。** 纯先定计划后执行时，`N-03` 那条合理的抄送请求
      被一起丢掉了——工单说了要抄送风控，但计划里没有这一步。
      **安全是用能力换来的**，这一列就是账单。
- [ ] 最后一行把代价买了回来：收件人白名单由**用户**预授权，工单说了不算。
      能力回来了，ASR 仍然是 0。
- [ ] 底部那段 A-07 的演示里，「隔离模型想做的事」与「实际执行的动作」是两行不同的东西。

## 变异检验（必做）

1. 在 `plan()` 里把 `input.ticketBody` 传进去，并让它按工单内容追加发送步骤——
   **ASR 必须立刻涨回去**。这一步会让你亲手把那道墙拆掉，看清它原来挡在哪。
2. 把 `runPlanned()` 改成「执行 `quarantinedRead()` 返回的动作」而不是计划里的步骤——
   同样应该涨回去。

两次都涨不回去，说明你的对照组根本没接上，表里的 0% 是假的。

## 另外四个模式

课程正文里讲了六个模式，这个实验只落地了其中两个（先定计划后执行、双模型隔离的简化版）。
另外四个——动作选择器、分片归并、先写程序后执行、上下文最小化——的取舍写在正文里。
**不要以为模式越多越安全**：每个模式都在用能力换安全，选型判据只有一条：
这个任务到底需不需要根据不可信内容改变动作。
