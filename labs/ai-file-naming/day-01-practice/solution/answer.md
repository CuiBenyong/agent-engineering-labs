# One suggested naming proposal

The convention is “content date_subject_status_version_source ID,” retaining the original extension. The date identifies the event related to the material, not the file creation date. Status and version are different fields; F IDs are paper mapping labels. All names are suggestions and no real file was operated on.

| ID | Original file name | Proposed name | Evidence and open questions |
| --- | --- | --- | --- |
| F01 | `2026-10-05_FairNotes_DraftA.docx` | `2026-10-08_FairNotes_Draft_v01_F01.docx` | Content date 10-08; fictional register says draft v01. |
| F02 | `FairNotes_Final.docx` | `2026-10-08_FairNotes_StatusUnknown_VersionUnknown_F02.docx` | Content date supplied; “Final” does not establish status or version. |
| F03 | `FairNotes_Revised.docx` | `2026-10-08_FairNotes_StatusUnknown_VersionUnknown_F03.docx` | Content date supplied; status and version remain unknown. |
| F04 | `2026-10-07_FairNotes_Confirmed.docx` | `2026-10-08_FairNotes_Confirmed_v02_F04.docx` | Content date 10-08; fictional register says confirmed v02. |
| F05 | `FairChecklist.docx` | `DateUnknown_FairChecklist_StatusUnknown_VersionUnknown_F05.docx` | Content date, status and version were not supplied. |

The fictional register explicitly places F04 v02 after F01 v01. It supplies no version relationship for F02, F03 or F05, and a later creation date does not establish a newer version. F04's confirmed status also does not mean it was published or is certainly the single final file.

Without source IDs, F02 and F03 would both map to `2026-10-08_FairNotes_StatusUnknown_VersionUnknown.docx`. Record both collision sources. The F02 and F03 suffixes distinguish this paper exercise but cannot guarantee uniqueness in an actual target folder; they do not authorize overwriting or deletion.

Explanation for a later reader: the date field means the related event date. Use the table to trace original names, proposals and source IDs.
