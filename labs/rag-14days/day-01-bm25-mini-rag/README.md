# D1 实验：一个不依赖任何向量库、用 BM25 检索并生成带出处回答的最小问答脚本

> 目标：不装向量库、不调 embedding 接口、不碰任何机器学习，用三百行左右的纯 TypeScript
> 把「切块 → 建索引 → 检索 → 组装上下文 → 生成」这条链路完整跑通一遍，
> 并把这一版的检索结果冻结成 `baseline.json`。后面十三天的每一项优化，都要跟这份基线比。

## 你会学到

- 准备一份三十篇短文档的语料，做最简单的分词与倒排索引
- 手写 BM25 打分，取前三条作为上下文，拼进提示词交给模型回答
- 让回答强制带上文档编号出处，问一个语料里没有答案的问题，观察它编不编
- 把 k1 与 b 两个参数各调一次，记录同一批问题的检索结果变化
- 把这一版的检索结果存成基线文件，后面每天的优化都跟它比

## 目录

```
day-01-bm25-mini-rag/
├── corpus/        30 篇虚构的「云梯科技」知识库文档，全课 14 天共用同一份
├── starter/       挖了 4 个练习点的起始代码，MOCK=1 下可以直接跑
└── solution/      参考答案，跑完会写出 solution/baseline.json
```

`starter/` 与 `solution/` 都用相对路径 `../corpus` 读语料，两边共用同一份，不要各自复制一份。

源码分五个文件，两边一一对应：

| 文件              | 干什么用                                                        |
| ----------------- | --------------------------------------------------------------- |
| `src/corpus.ts`   | 读 `corpus/*.md`，解析 frontmatter 的四个字段                   |
| `src/tokenize.ts` | 中英混合分词：中文二元组、英文按词（**练习 1**）                |
| `src/bm25.ts`     | 倒排索引、逆文档频率、BM25 打分（**练习 2、3**）                |
| `src/generate.ts` | 组装上下文与提示词；唯一的网络出口，`MOCK=1` 在这里换成模板拼接 |
| `src/index.ts`    | 命令行入口、基线问题集、`baseline.json`（**练习 4**）           |

## 语料说明

`corpus/` 是**为本课原创**的虚构语料，主体是一家叫「云梯科技」的 SaaS 公司，产品是团队协作工具「云梯协作」。
30 篇按部门分四类：产品手册 10 篇（`product`）、内部制度 6 篇（`hr`）、技术架构 6 篇（`eng`）、
客服问答 5 篇（`support`）、会议纪要 3 篇（按主题分别归到 `product` / `eng` / `hr`）。
每篇 frontmatter 固定四个字段：`id`、`title`、`department`、`updated`。语料按 MIT 许可随本课分发。

里面**故意埋了三样东西**，后面几天会用到，现在先知道它们存在：

1. **两篇结论互相矛盾的文档**：`doc-006`（产品手册，2026-08-20）写单文件上限 200 MB、回收站保留 30 天；
   `doc-024`（客服问答，2025-11-03）写 100 MB、7 天。`doc-028` 的周会纪要里点破了这件事。
2. **一个必须跨两篇才能回答的事实**：`doc-019` 说生产库主备切换要「平台组组长」书面审批，
   而「平台组组长是周敏」写在 `doc-014` 里。纯 BM25 检索只能捞到前者。
3. **一段排版糟糕的表格**：`doc-005` 的套餐配额表分隔符缺列、还混着一段用制表符对齐的纯文本表。

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env  # 填 ANTHROPIC_API_KEY；没有 key 就一直用 MOCK=1

MOCK=1 pnpm start                          # 跑 9 个基线问题，写出 baseline.json
MOCK=1 pnpm start "回收站能保留多久"        # 问单个问题
K1=5 MOCK=1 pnpm start                     # 调词频饱和系数再跑一遍基线
B=0 MOCK=1 pnpm start                      # 关掉长度归一化
pnpm start "回收站能保留多久"               # 去掉 MOCK 走真实模型
```

> `pnpm install --ignore-workspace` 可能以非 0 退出并打印 `[ERR_PNPM_IGNORED_BUILDS]`，
> 这只是 pnpm 拦了 esbuild 的构建脚本，依赖已经装好了。以 `pnpm typecheck` 和 `pnpm start` 的结果为准。

### MOCK 说明

`MOCK=1` 只替换**生成**这一步：不调用模型，改成把每篇命中文档里与问题重合度最高的那一句摘出来、
带上 `[doc-006]` 这样的编号列出来。切块、建索引、检索、阈值过滤全都真实执行，
所以离线也能看到真实的检索现象——包括两篇材料打架、包括该拒答时拒不拒。
换句话说：**`MOCK=1` 验证的是代码路径和检索行为，不是模型的生成质量。**

### 基线文件长什么样

`baseline.json` 记录一批固定问题（`b01`…`b09`）在当前参数下的检索结果：

```json
{
  "generatedAt": "2026-09-06T...",
  "retriever": "bm25",
  "params": { "k1": 1.2, "b": 0.75, "topK": 3, "minScore": 6 },
  "corpus": { "docCount": 30, "avgTokens": 413.8 },
  "questions": [
    {
      "id": "b01",
      "question": "单个文件最大能上传多大？",
      "hits": [
        {
          "rank": 1,
          "docId": "doc-024",
          "score": 9.1103,
          "title": "常见问题：文件上传失败与文件找回",
          "department": "support"
        }
      ],
      "used": ["doc-024", "doc-006"],
      "refused": false
    }
  ]
}
```

`hits` 是打分后的前 K 名，`used` 是过了阈值、真正进上下文的那几篇，`refused` 表示这一问最后有没有拒答。
后面各天换了检索方式之后，对着这三个字段看变化就够了。

## 验收标准

1. `MOCK=1 pnpm start` 能打印出 9 个基线问题的前三名，每行带分数、文档编号、标题和部门，并在结尾写出 `baseline.json`。
2. b01（单个文件最大能传多大）的前两名同时是 `doc-024` 和 `doc-006`，回答里两个编号都出现——你亲眼看到了两篇材料结论打架。
3. b03（主备切换谁审批）能命中 `doc-019`，但答案止步于「平台组组长」，`doc-014` 一次都没进前三——这就是纯关键词检索答不了多跳问题的现场。
4. b08（团建预算）走到拒答，b09（报销手机话费）却仍然拼出了一段不相干的内容——说明分数阈值挡得住一类问题，挡不住另一类。
5. 把 `K1` 从默认的 1.2 改成 5 再跑一遍，b04 的第三名从 `doc-022` 变成 `doc-014`；改成 0.2 再跑一遍，b07 的第二三名互换。两次结果都能跟默认参数的 `baseline.json` 对上差异。

## 常见坑

1. **用 `process.cwd()` 去找语料。** `corpus/` 在 lab 根目录，`starter` 和 `solution` 各在下一层。
   用 cwd 拼路径的话，从别的目录敲命令就会「语料目录是空的」。`src/corpus.ts` 里是从
   `import.meta.url` 往上两级定位的，这样跟你在哪儿敲命令无关。
2. **中文直接按空白切词。** 这是 starter 里练习 1 的默认写法，跑出来每个问题都是「一个词都没命中」。
   中文没有空格，必须自己切；二元组是零依赖场景下最划算的做法。
3. **同分不给决胜键。** 两篇文档分数一模一样时，`Set` 与 `Map` 的遍历顺序决定谁排前面，
   换个 Node 版本或者改一下语料顺序，`baseline.json` 就对不上了。这里显式加了按 `docId` 的次级排序。
4. **忘了给分数设下限。** 不过滤的话，任何问题都会捞回三篇「最不相干里最相干」的文档，
   然后模型对着这堆东西一本正经地编。但也别指望阈值能解决全部问题——b09 就是分数很高却依然无解的反例，
   那一层要靠提示词里「找不到就只回这一句」来兜。
