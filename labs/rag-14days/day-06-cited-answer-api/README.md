# D6 实验：一个带引用校验、拒答策略与流式输出的问答接口

> 目标：把检索结果变成**可验证**的回答。模型标出来的每一个出处，都要由代码回查一遍原文才准发给用户；
> 材料不支持的时候，接口要能闭嘴，而且三种闭嘴的说法各不相同。

## 你会学到

- 写一个组装函数：按分数排序、去重、控制总 token 预算，并保留块编号
- 设计提示词让模型逐句标注出处，拿到结构化的回答与引用列表
- 实现引用校验：编号必须存在、被引块必须与该句有实质重合，否则打回重生成
- 加两条拒答规则并各构造一个触发用例
- 把接口改成流式，先流正文再补校验过的引用块

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env  # 填 ANTHROPIC_API_KEY；没有 key 先用 MOCK=1
MOCK=1 pnpm start     # 起服务 → 跑自测 → 逐项打印 ✅/❌ → 退出
MOCK=1 SERVE=1 pnpm start   # 常驻，供你自己 curl
pnpm start            # 真模型（生成用 claude-sonnet-5，上下文压缩用 claude-haiku-4-5-20251001）
```

服务端口是 **3056**（本课口径：3000 + 天号，D6 的天号是 56）。常驻之后可以这样试：

```bash
curl -s localhost:3056/ask -H 'content-type: application/json' \
  -d '{"question":"单个文件最大能上传多大？"}'

# 看流式：编造引用的那两句会以 dropped 事件出现，不会进正文
curl -N -s localhost:3056/ask/stream -H 'content-type: application/json' \
  -d '{"question":"开放 API 的默认限流是多少？","fabricate":true}'

# 回查某个引用的原文
curl -s localhost:3056/chunk/doc-006/c01
```

## 练习点

`starter/` 是一个能跑起来的完整服务，只有四处被挖空。原样跑 `MOCK=1 pnpm start` 会看到 **4/8 项通过**，
做完这四处应该变成 **8/8**：

| #   | 位置                                               | 挖空后的现象                                                                     |
| --- | -------------------------------------------------- | -------------------------------------------------------------------------------- |
| 1   | `assemble.ts` 的 token 预算与 `interleaveHeadTail` | 材料不看预算照单全收，且第 2 名被放在中间——正是最容易被读漏的位置                |
| 2   | `verify.ts` 的 `overlapRatio`                      | 只校验了编号存不存在。「编号是真的、内容对不上」那一类编造一路放行               |
| 3   | `verify.ts` 的 `detectConflict`                    | 「单个文件最大能传多大」拿到一个看起来很确定的答案，而语料里两篇文档的说法不一样 |
| 4   | `server.ts` 流式路由里的 `flush`                   | 收到什么发什么，编造的引用已经到用户屏幕上了，撤不回来                           |

## 验收标准

1. `MOCK=1 pnpm start` 在 `solution/` 里 8/8 全绿；在动手之前的 `starter/` 里是 4/8。
2. 组装那一项打印出的块编号顺序里，最高分的块在开头、第二名在结尾，材料 token 不超过 `CONTEXT_BUDGET`。
3. 引用校验那一项能同时抓住两种编造：「不存在的块编号 [8]」和「[2] 的实质重合度只有 0.03」，
   并且第 2 版重生成之后返回的引用编号全部落在发出去的范围内。
4. 三条拒答线各触发一次，且话术互不相同：团建预算走 `low_score`、上传上限走 `conflict`
   （回答里并排列出 200 MB 与 100 MB 及各自的更新日期）、报销手机话费走 `unsupported`。
5. 流式那一项的事件序列是 `meta → sentence → dropped → dropped → done`：编造的两句以 `dropped` 出现，
   真正发出去的每一句都带着已核实的引用。

## MOCK 说明

`MOCK=1` 下**不需要网络、不需要 API key**。被 mock 掉的只有两个网络出口（生成与上下文压缩），
换成确定性的模板化实现：从每一块里摘出与问题重合度最高的一句，带上它自己的编号；一块都摘不出来就
输出一条没有出处的结论。

**引用校验、拒答判定、组装、压缩的那道「必须逐字来自原文」的硬约束，在 MOCK 下全部真实执行。**
这是本天的重点，把它们一起 mock 掉这一天就白做了。`fabricate: true` 是一个演示开关，它让模板生成
在第一版里故意混进两条编造引用——真实模型不需要这个开关也会编，但那不可复现，写不进自测。

顺带一提，本课统一的 mock embedding（确定性哈希向量）今天用不上：D6 全程只用 D1 的 BM25 检索，
重点在生成侧。

## 常见坑

1. **校验只查编号存在性等于没查。** 模型编引用最常见的形态不是编一个不存在的编号，而是引一个真实存在、
   但根本没说这句话的块。只有算「这句话与被引块的实质重合度」才拦得住，而算重合度时必须先把
   「云梯」「文件」这种块块都有的词剔掉，否则随便引哪一块都能及格。
2. **校验要拿原文比对，不能拿压缩后的材料比对。** 上下文压缩之后放进提示词的是删过句子的版本，
   但用户点开引用看到的是原文。校验对象一旦跟用户看到的东西不是同一份，「校验通过」就什么都保证不了。
3. **压缩的小模型会顺手改写。** 提示词里写了「逐字保留」也拦不住，所以代码里必须再加一道硬约束：
   保留下来的每一句都要能在原文里逐字找到，找不到就整块回退成未压缩版本。
4. **冲突检测不加上下文键会疯狂误报。** 只比「单位相同、数值不同」的话，「回收站保留 30 天」和
   「试用期 90 天」会被判成冲突。必须再要求两个数字前面的上下文至少共享两个词元。
5. **流式一旦吐出去就撤不回来。** 想既流式又不放跑错误引用，只能按句缓冲：攒够一句校验一次，
   通过了才发。代价是首字延迟从一个 token 变成一句话——这个代价是必须付的。
