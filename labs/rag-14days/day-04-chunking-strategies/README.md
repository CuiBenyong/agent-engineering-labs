# D4 实验：五种切块策略的并排实现与同一批问题下的命中率对照表

> 目标：把固定长度、递归、按结构、父子、语义五种切法实现在同一个接口下，用同一份语料各切一遍，
> 再用十个带标准答案文档的问题在**同一个 token 预算**下量出它们的命中率，
> 最后给其中一种加上上下文块头，看命中率和 token 成本各变了多少。
> 做完这个实验，「块该切多大」这个问题在你这里就不再是拍脑袋，而是一条命令。

## 你会学到

- 实现固定长度、递归、按标题、父子、语义五个切块器，统一输出接口
- 用同一份语料各切一遍，统计块数、块长分布与切碎的句子比例
- 用十个带标准答案文档的问题，量出每种切法的命中率
- 给其中一种切法加上上下文块头，看命中率变化和 token 成本增加了多少
- 写下你的选型结论和它成立的前提条件

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env  # 语义切分要 OPENAI_API_KEY，块头要 ANTHROPIC_API_KEY；没有就一直用 MOCK=1

MOCK=1 pnpm start     # 三张对照表 + chunking-report.json，全程离线
pnpm start            # 语义切分走真实 embedding，块头走真实模型
```

> `pnpm install --ignore-workspace` 可能以非 0 退出并打印 `[ERR_PNPM_IGNORED_BUILDS]`，
> 这只是 pnpm 拦了 esbuild 的构建脚本，依赖已经装好了。以 `pnpm typecheck` 和 `pnpm start` 的结果为准。

### MOCK 说明

`MOCK=1` 换掉两处网络出口：`src/embed.ts` 的向量接口换成确定性哈希向量，
`src/header.ts` 的块头生成换成按标题路径拼的规则版。**切块、统计、检索、命中率判定全都真实执行。**

哈希向量保留的是**字面重合度**，所以离线模式下的语义切分行为接近「按用词是否突变来断句」，
而不是真正的语义。**`MOCK=1` 验证的是代码路径和切块行为，不是 embedding 的语义能力。**

### 评估口径（三条，看数字之前先看这个）

1. **命中判据**：`single` 类问题，`answerDocIds` 里任意一篇进了上下文就算命中；
   `multi` 类问题，必须**全部**答案文档都进上下文才算命中；`none` 类不计入命中率，
   只报它的最高分，供第六天定拒答阈值时参考。
2. **同一把尺子是 token 预算，不是「取前几块」。** 按名次往上下文里装块，装满 600 token 就停。
   按条数比是不公平的——固定长度 400 字取 5 块塞进去两千多 token，语义切分取 5 块只有几百，
   赢的那一方只是买了更多货。
3. **本天只用最朴素的一个指标：答案文档有没有进上下文。** 召回率、精确率、忠实度、
   模型裁判这一整套完整的评估体系是第八天的事，那时候这 10 题会扩成 20 题，前 10 题原样保留。

## 验收标准

1. `MOCK=1 pnpm start` 打印出三张表：块级统计、命中率对照、加块头前后对比，并写出 `chunking-report.json`。
2. 第一张表里，**固定长度的切碎率接近一半（48.3%），递归只有 1.6%**——两者块数几乎一样，
   差别全在「切在哪」。你亲眼看到分隔符优先级值多少钱。
3. 第二张表里，**固定长度与递归是 6/8，按结构、父子、语义是 7/8**；
   同样 600 token 的预算，前两者平均只装得下 1.2 块，后三者能装 2.5 到 4.8 块。
4. q06（主备切换谁审批、叫什么名字）**五种切法全部未中**——切块解决不了多跳，那是第十天和第十二天的事。
5. 第三张表里，加上上下文块头之后**命中率没有变化，索引 token 涨了 10.4%，答案文档平均名次还从 2.88 退到 3.25**。
   这是这份语料上的真实结果，不是块头没用，是它对纯关键词检索本来就会稀释——完整结论见正文。

## 常见坑

1. **按「取前 k 块」比不同切法。** 这是这个实验最容易做错的一步。k 固定时，块越大塞进去的字越多，
   大块切法会赢在「买得多」上，而不是赢在「切得准」上。改成按 token 预算装，结论会反过来。
2. **语义切分把相似度阈值写死成一个绝对值。** 不同 embedding 模型的相似度分布完全不同，
   0.55 换个模型就变成「全断」或「全不断」。这里用的是分位数：只在本篇最不像的那 25% 处断开，
   再加一个最小块长兜底，否则会切出一大堆几十个字、根本没有语境的碎块。
3. **重叠区越大越好。** 重叠是有代价的：`FIXED_OVERLAP` 从 0 调到 80，索引 token 从 15641 涨到 18002
   （涨 15%），而且相邻块内容重复，检索结果会彼此冗余，前几名可能是同一段话的三个版本。
4. **忘了同分决胜键。** 块级检索的候选比篇级多几倍，同分的概率也高几倍。
   `src/bm25.ts` 里显式加了按 id 的次级排序，去掉它换台机器跑出来的名次就对不上了。
