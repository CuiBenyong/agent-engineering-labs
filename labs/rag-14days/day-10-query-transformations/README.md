# D10 实验：四种查询变换加意图路由的实现，以及它们在评估集上的收益与成本对照

> 目标：把「用户原样打进来的那句话」换成一个或几个更适合检索的检索式——改写、假设文档、多路查询、后退提问——再加一层意图路由决定要不要检索；然后在第八天那 20 道题上逐个开关，用指标、模型调用次数和上下文 token 三笔账，挑出一份**默认配置**。检索器一行都不改，所以指标的任何变化都只可能来自查询侧。

## 你会学到

- 实现查询改写与指代消解，用一段多轮对话验证效果
- 实现假设文档嵌入与多路查询，复用第九天的融合逻辑
- 写一个轻量意图分类，把问题分流到直接回答、单跳检索、多跳检索三条路
- 在评估集上逐个开关这些手法，记录指标变化与额外调用次数
- 给出一份默认配置，说明你为什么关掉了其中某几项

## MOCK 说明（读完再看数字）

`MOCK=1` 换掉两样东西，**只有这两样**：

1. **embedding** 换成确定性哈希向量（全课统一实现，见 `src/embed.ts`）。它保留字面重合度，
   所以 mock 下的向量检索行为接近关键词检索——**验证的是代码路径，不是检索效果**。
2. **五次模型调用**（改写、假设文档、多路查询、后退提问、意图分类）换成**确定性规则替身**。
   规则替身只认几张写死的词表：疑问词、口语填充词、角色词（`ROLE_RE`）、文档交叉引用（`《…》`）。

**手法本身的逻辑没有被 mock。** 检索式怎么拼、几路怎么用倒数排名融合合起来、路由怎么分流、
预算怎么分配，MOCK 与真实模式跑的是同一份代码。

所以下面那张表要这么读：**列里的「模型调用」「检索次数」「上下文 token」是实的，
「召回率」「MRR」「nDCG」只说明这条代码路径通了、方向对了，不代表真实模型能拿到同样的收益。**
差得最远的是假设文档嵌入：真实模型会**编一个具体答案**（编出「上限 300 元」这种数字），
那才是它拉近查询与文档距离的关键；规则替身编不出具体内容，只能补文体词，
所以 MOCK 下 HyDE 的效果被明显低估。**想知道这几种手法在你的数据上值不值，只能连上模型自己跑一遍。**

「估算延迟」那一列也不是实测：`LATENCY_PER_CALL_MS` 是**占位值**（默认 900ms），
只用来把「多几次调用」换算成「多几秒」。真实延迟随模型、区域、并发而变，要自己测。

## 读这张表之前：两列指标是死的，别看错地方

D8 的基线报告里有两项已经**顶格**，今天开关任何手法它们都不会动，拿它们当改进证据等于自欺：

- **MRR = 1.0000**。题目是从语料反向出的，字面重合度高，加上 mock 哈希向量本身保留字面重合，第一名永远是答案文档。**这是指标饱和，不是系统满分。**
- **单文档召回率 = 100.0%**。single 那一档没有提升空间了。

所以**今天全部的证据只能出在三个地方**：multi 档召回率（基线 50.0%）、nDCG@10（基线 0.6711）、无答案题拒答率（基线 0.0%）。表里保留 MRR 那一列，是为了让你亲眼看到它一动不动——**看到一列全是 1.0000，第一反应应该是「这把尺子坏了」，而不是「我的系统很棒」。**

## 两道多跳题为什么原本会失败，又分别被什么修好

D8 的基线在 multi 档只有 50%，失败的两道**病因完全不同**，值得你自己在 `reports/latest.json` 里对着候选池确认一遍：

| 题    | 基线为什么失败                                                                                                                       | 被什么修好                                                                                                                     |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `q06` | 第二篇答案文档 `doc-014` **一次都没进候选池**（`doc-019` 只写了「平台组组长」这个角色，`doc-014` 才写了名字，两篇字面零重合）        | 多跳桥接那一轮拿角色短语「平台组组长」重新检索，把它捞进候选池（rank 5，bm25 27.28 自己过闸），再靠加高的预算装进上下文        |
| `q07` | 第二篇答案文档 `doc-021` 基线里已经排到 **rank 4，但两路原始分都没过门槛**（bm25 = 0.00、cos = 0.151，差 0.049），被拒答闸门挡在外面 | 桥接那一轮用正文里《变更评审规范》这个交叉引用去查，同一篇文档拿到 bm25 45.09 / cos 0.475，**以自己的原始分过闸**并升到 rank 1 |

**「候选池里根本没有」和「候选池里有但被挡住」是两种病。** 前者只能靠换检索式（多路查询、后退提问、桥接检索）去捞，重排、融合、调门槛都变不出没捞到的东西；后者是门槛问题，多加一路检索让它拿到自己的高分是最干净的解法——**注意这里靠的正是「门槛卡原始分不卡融合分」这条不变量**，否则 `q07` 的修复根本不会发生。

## 默认配置的取舍（这一节是本实验真正的产出）

默认打开**查询改写 + 意图路由（多跳分预算）**，其余三项默认关闭。逐条给理由：

| 手法                   | 默认   | 理由                                                                                                                                                                                                                                                                                                                                                                          |
| ---------------------- | ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 查询改写               | **开** | 在这 20 道**单轮**题上收益是 0（表里那一行和基线一模一样），但多轮对话里它是**能不能答**的分界线：第 2 轮的「这个人」不消解，一条候选都过不了门槛，系统只能拒答。单轮免费、多轮救命，没有理由关。                                                                                                                                                                             |
| 意图路由（多跳分预算） | **开** | 唯一一项**既省钱又涨指标**的手法：闲聊那一轮零检索；多跳题被认出来后拿到 1000 token 预算，multi 召回率 50% → 100%。每题只多一次很短的分类调用。                                                                                                                                                                                                                               |
| 假设文档嵌入           | 关     | **关它的理由是成本，不是效果——因为效果这一栏我们根本没资格填。** 离线下这一步是规则替身，只会套文体词，编不出「上限若干元」这种具体内容，而那正是 HyDE 起作用的地方；表里那 +6.3 个点**既不能证明 HyDE 有用，也不能证明它没用**。能确定的只有成本：检索次数翻倍，每题多一次**长输出**调用（80–150 字，比其他四项贵一个数量级）。**默认关，连上真模型之后当第一个 A/B 项跑。** |
| 多路查询               | 关     | 这份数据上**净负收益**：召回率没动，nDCG 从 0.671 掉到 0.665，检索次数却从 20 涨到 60（三倍）。原因不难理解——语料只有 30 篇 134 块，本来就没有「换个角度才能捞到」的长尾，多出来的两路只是把同一批结果重新洗了一遍牌。**语料上万篇再回来重测**。                                                                                                                              |
| 后退提问               | 关     | 效果这一栏和 HyDE 同样打问号（离线下也是规则替身），但它**输出短**，是四种扩展手法里最便宜的一个。默认关的理由是收益**重叠**：离线数据显示它救的是和「路由 + 分预算」同一批多跳题，而路由更便宜。**如果你的场景没法做路由，那就开它。**                                                                                                                                       |

一句话版本：**默认配置里只留下「不开就答不了」和「开了还省钱」的两项，其余三项都进 A/B 队列，等有了真实流量再定。**

注意这份取舍的依据结构：留下的两项**理由都不依赖离线指标**（改写靠的是「不消解就只能拒答」这个可复现的现象，路由靠的是「闲聊零检索」和「多跳分预算」这两笔算得清的账）；关掉的三项里，多路查询是**离线就看得出负收益**（nDCG 掉了、检索次数三倍），另外两项是**离线根本判不了效果、只判得了成本**。**别把「离线没测出收益」写成「这个手法没用」。**

## 常见坑

1. **路由放在改写前面，指代词会把路由也带偏。** 「这个人叫什么名字？」里的「这个人」是多跳信号词，
   路由会判成 multi-hop，白跑一轮桥接检索；改写成「平台组组长叫什么名字？」之后它就是个普通单跳问题。
   本实验的 `runQuery` 里顺序写死了：**先改写，再路由，扩展类手法都建立在改写后的那句话上**。
2. **融合分不能拿去判拒答。** 倒数排名融合出来的分是相对的，最不相干的那一批也能拿到最高分。
   `fuseCandidates` 保留了每一路给出的**原始最高分**，拒答判定仍然踩在绝对分上——
   这是 4 道 `none` 题不被假设文档带偏的最后一道闸。把 `admitted` 改成看融合分，
   拒答率会立刻掉到 0，而报表上的召回率一点都不会变，你根本发现不了。
3. **假设文档不要直接替换原问题。** 经典 HyDE 是用假设文档**代替**查询去做向量检索；
   本实验把它当成**第二个检索式**参与融合，因为模型编歪时替换会把原问题的信号一起丢掉，
   而融合最多是稀释。要试经典版就把 `pipeline.ts` 里 `queries.push` 改成替换，然后重跑评估看数字。
4. **角色短语的正则会把前面的动词一起吃进来。** `ROLE_RE` 在「必须由平台组组长书面审批」上
   匹配出的是「必须由平台组组长」，直接拿去检索会引入噪声词。`ruleRewrite` 里按连接词切了一刀只留最后一段。
   这类补丁正是规则替身的天花板——**真实改写器读的是上下文，不是词表**。
5. **别用「全开」当默认配置。** 全开这一行的召回率和「默认配置」一模一样，模型调用却是它的 2.5 倍、
   检索次数是 4.3 倍。堆手法很容易，说清楚为什么关掉某几项才是这一天的作业。
6. **别拿 MRR 当改进证据。** 它在这份题集上恒等于 1.0000（指标饱和，见上面那一节），
   你把任何一项手法打开或关掉它都不会动。同理单文档召回率已经 100%，
   **一切改进只可能显示在 multi 召回率、nDCG 和拒答率上**。
