## 手动验收清单

自检全绿**不等于**做完了。下面几条要你亲眼看一遍：

- [ ] `MOCK=1 pnpm start` 的输出里，`pass@5` 明显高于 `pass^5`。
      如果两个数字相等，说明你的靶子没在抖，回头检查 `--seed` 是不是把随机性锁死了。
- [ ] 跑 `MOCK=1 pnpm start -- --seed 42` 两次，输出**逐字相同**。
      可复现是 D6 回归门禁能成立的前提。
- [ ] 跑 `MOCK=1 pnpm start -- --seed 7` 和 `--seed 99`，输出**不同**。
      两件事要同时成立：同种子可复现、换种子会变。
- [ ] 把 `--k` 从 5 调到 20，观察 `pass^k` 怎么变化。
      想清楚为什么 k 越大这个数字越低，以及这是不是意味着 Agent 变差了。
- [ ] 打开 `src/agent/target.ts`，找到 `DEFECT_RATES` 那三个数字。
      它们是**故意**留的缺陷，是你接下来六天要用评估抓出来的东西。

## 两个指标的含义

| 指标     | 问的问题                                     | 什么时候用                               |
| -------- | -------------------------------------------- | ---------------------------------------- |
| `pass@k` | k 次里**至少成一次**的概率                   | 有人工兜底：生成候选、写代码草稿         |
| `pass^k` | k 次**全部成功**的概率，等于 `p` 的 `k` 次方 | 面向客户、没有兜底：客服、支付、自动执行 |

单次成功率 75% 的 Agent，连成三次的概率是 `0.75³ ≈ 42%`。
**一个「四次里成三次」的 Agent，放到需要连续可靠的场景里，其实一半以上的时间是坏的。**
这两个指标的定义出自 τ-bench 论文（arXiv 2406.12045）。
