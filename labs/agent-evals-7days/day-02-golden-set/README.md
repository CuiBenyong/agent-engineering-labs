# D2 实验：把线上翻过的车变成一份基准集

D1 用三条示例任务演示了「同一个任务跑五次分数会抖」。今天要建的是真正能用的那一批：
**24 条正反配对的任务，外加一个在你拿它去考 Agent 之前先把它自己考一遍的验证器。**

跑完这一天，你手里会有一份能进 git、能被非工程师 review、能在 D6 被 CI 读取的基准集，
以及一个回答这个问题的工具：

> 这条任务没通过，是 Agent 不行，还是题目本身写错了？

| 文件                    | 说明                                                       |

## 跑起来

```bash
cd starter
pnpm install --ignore-workspace
MOCK=1 pnpm selftest        # 现在应该红 5 项，这是正常的
```

> `pnpm install --ignore-workspace` 可能以非 0 退出并打印 `[ERR_PNPM_IGNORED_BUILDS]`，
> 这**不代表安装失败**。看 `node_modules` 有没有生成、以及 `pnpm typecheck` 过不过，那两个是准的。

## 今天的练习

**练习 1：`src/core/suite.ts` 的 `validateSuite`。** 基准集是 JSON，没有类型检查兜底，
所以要有一个校验器把「手写 JSON 会犯的错」挡在门外。要挡的不是语法错误，
而是**语义写错但跑得起来**的那些。其中两条最值得记住：

- `expect.refunds` 的金额必须与订单金额一致。写错一分钱，这条任务会**永远判失败**，
  而失败原因看起来像是 Agent 的错。
- `prompt` 里提到的订单号必须真的在 `seed.orders` 里。漏了这条，任务会**永远通过**：
  Agent 查不到订单于是什么都不做，而期望恰好也是什么都别做。

**练习 2：`splitSuite`。** 按集合标签把基准集拆成能力集与回归集。

**练习 3：`src/core/reference.ts` 的 `verifySuite`。** 用参考解 + 两个退化解逐条体检：
参考解过不了 → 任务本身可疑；三个都过得了 → 这条任务没有区分度。

做完之后：

```bash
MOCK=1 pnpm selftest        # 十项全绿才算过
MOCK=1 pnpm start           # 看能力集与回归集分开之后的两个数字
```

## 手动验收清单

自检全绿**不等于**做完了。下面几条要你亲眼看一遍：

- [ ] `MOCK=1 pnpm start` 的输出里，**回归集是 100%，能力集明显低于它**。
      如果两个数字差不多，回头检查 `splitSuite` 是不是把标签认错了。
- [ ] 看一眼总分那一行。它介于两者之间，**既不能报警也不能指方向**——
      这就是「两类评估混在一个套件里」的代价，今天这份报告是它的实物证据。
- [ ] 手工把 `src/tasks/golden.json` 里任意一条任务的 `expect.refunds` 金额改掉一分，
      跑 `MOCK=1 pnpm start`。它应该在**校验阶段**就被拦下，而不是跑完之后报一个低分。
      改回来。
- [ ] 手工把某条反向任务的 `polarity` 改成 `positive`，再跑一次。
      校验器应该报「正向任务必须至少期望一笔退款」。改回来。
- [ ] 把 `golden.json` 里 12 条反向任务**全部删掉**，跑 `MOCK=1 pnpm start`。
      分数会**变高**——因为见谁都退款的那个缺陷只在反向任务上扣分。
      这是「只测正向会养出什么」最直观的一次演示。看完记得 `git checkout` 还原。
- [ ] 打开 `src/core/reference.ts`，确认参考解**完全没有读 `task.polarity`**。
      想清楚为什么：偷看了极性的参考解，验证的只是「我抄对了答案」。

## 三个数字的含义

| 集合   | 条数 | 期望的通过率     | 掉下来说明什么                     |
| ------ | ---- | ---------------- | ---------------------------------- |
| 回归集 | 10   | 长期贴近 100%    | **退化**，有人改坏了已经修好的东西 |
| 能力集 | 14   | 从低起步，慢慢爬 | 一上来就满分说明题出得太简单       |
| 总分   | 24   | ——               | 这个数字不该出现在你的看板上       |

起步不必等攒够几百条：**20 到 50 条来自真实失败的任务就足够开工**。
