# D6 实验：一个把六类故障各自处理到位、随时可取消、不会无限打转的稳定循环

> 目标：把「Agent 一遇到意外就崩、或者一头撞死在同一个动作上」这件事彻底解决掉。
> 六类故障各注入一次，看它们分别走到回灌自纠、退避重试、向用户抬头哪一条路；
> 再把取消信号从按键一路接到子进程，验证一次真的杀掉了卡死的命令。
> 现象最好看的一条：起点代码里「断流也重试」这个错误默认值，会让同一句话在屏幕上打印三遍。

## 你会学到

- 实现错误分类函数，把六类注入故障映射到回灌、重试、抬头三种处理路径
- 给网关层加带抖动的退避重试，只对限流与网络错误生效，而且只在「还没吐字」时才重试
- 把取消信号从按键接到子进程，验证一次真的杀掉了卡死的命令
- 实现重复调用检测与轮数、时长、用量三条硬上限，触发时打断并向模型说明
- 自检里逐个打开六种注入，断言每种都走到了预期分支

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env

# 验收入口：全课二十一天统一用这一条
MOCK=1 SELFTEST=1 pnpm start

# 交互着看基准任务（第二行的 y 是回答审批提示）
printf '帮我修一下失败的测试\ny\n/exit\n' | MOCK=1 pnpm start

# 六类故障各看一次。前五条不需要回答审批，最后两条要
INJECT=rate_limit  # 第一次 429，退避之后重试成功，任务照常完成
INJECT=truncated   # 吐过字之后断流：不重试，保留已收到的内容
INJECT=bad_args    # 参数非法被逐次回灌；这一段故意自纠不成功，最后向用户抬头
INJECT=loop        # 同参数连调三次，第三次被打转检测挡下
INJECT=timeout     # 命令卡死被超时杀掉，回灌里带着「把命令拆小」
printf '帮我修一下失败的测试\n/exit\n' | MOCK=1 INJECT=loop pnpm start
printf '帮我修一下失败的测试\ny\ny\n/exit\n' | MOCK=1 INJECT=tool_error pnpm start

# 取消链路：跑一条要十五秒的命令，允许它之后按 Esc（或 Ctrl+C）打断
MOCK=1 pnpm start
# 你 > 跑个长命令，不要停
```

> `pnpm install --ignore-workspace` 可能以非 0 退出并打印 `Ignored build scripts: esbuild`，
> 这不代表安装失败——看 `node_modules` 有没有生成、`pnpm typecheck` 过不过就够了。

> **Esc 只在真终端里有效。** 管道与 CI 里没有 keypress 事件，所以那种环境下按键这一环不存在，
> 自检改成直接触发 AbortController 来验后面三环。`isCancelKey` 单独抽成函数就是为了能被断言。

## 验收标准

- [ ] `MOCK=1 SELFTEST=1 pnpm start` 打印 `11/11 通过`
- [ ] `INJECT=rate_limit` 时终端上出现一行 `↻ 网关这次没成功…等 xxx ms 再试第 2 次`，随后任务照常做完（等待毫秒数带抖动，每次都不一样）
- [ ] `INJECT=truncated` 时**不重试**：只打印收到的 3 个分片与一行断流说明；起点代码里同一句话会打印三遍，改完 `TODO(1)` 之后只打印一遍
- [ ] `INJECT=loop` 时第三次同参数调用被挡下（终端显示 ✘ 与「你已经用完全相同的参数调用 read_file 3 次了」），随后模型自己给出结论
- [ ] `INJECT=timeout` 时命令在 2 秒左右被杀掉，回灌里带着「把命令拆小」；跑完 `ps` 看不到残留的 node 进程
- [ ] 输入「跑个长命令，不要停」并批准之后按 Esc，命令在一秒内就停了（它自己要跑十五秒）

## 常见坑

- **重试的前提是这次尝试没留下用户已经看见的痕迹。** 限流是在第一个字节之前失败的，可以悄悄重试；断流是吐了一半才断的，重试会让同一段话说两遍——那不是恢复，那是错乱。判据就是「这次尝试已经吐出去几个分片」，代码里是 `emitted`。
- **不要重试整轮，只重试网关这一层。** 工具失败重试整轮，会把「已经改了一半的文件」再改一遍。重试的前提是这一步幂等，而写工具天生不幂等，所以工具失败走回灌。
- **退避必须加抖动。** 固定间隔会让同时被限流的一批进程一起等、一起撞、再一起等，把限流拖成周期性雪崩。也不要写成「0 到窗口之间随机」——那有可能抽到几毫秒，等于没退避。
- **网关给了 `retry-after` 就把它当下限。** 它比你的猜测准；本课的实现是「退避算出来的值与它取大者」。
- **取消要落到最外层的系统资源上才算取消。** 只在循环里判断 `signal.aborted`，你会看到「已打断」立刻出现，但那条命令还在跑。四环缺一不可：按键 → `AbortController` → `fetch` 的 signal → 子进程的整个进程组。
- **打转检测比参数原文，不比语义，而且只看连续。** 参数只差一个空格就算不同的调用——它至少在尝试新东西；中间插进过别的调用就重新计数，因为「读文件、跑测试、再读同一个文件」是正常的验证节奏。
- **一条上限不够。** 轮数挡不住「一轮转十分钟」，时长挡不住「上下文越滚越大」。三条要一起有，而且触发时要报出是哪一条。
- **花费上限只按 token 数算，不折算金额。** 单价随网关与模型变，写进代码就等于把项目绑在某一家的价目表上。
- **回灌不是万能的。** `INJECT=bad_args` 那一段是故意让它自纠不成功的：模型连着四次都没能给出合法参数。这就是硬上限存在的理由——**自纠是第一道，硬上限是最后一道，两道都得有。**
- **注入点要写在它该发生的那一层。** 限流、断流、参数非法在离线剧本引擎里（`providers/mock.ts`，冻结），工具失败在 `edit-file.ts`，命令超时在 `command.ts`。剧本只负责演出「收到失败之后模型怎么做」。
- **`INJECT` 是在模块加载时读一次的**，同一个进程里改 `process.env.INJECT` 没有用。所以自检里要切换注入的那几项，一律起子进程跑。
