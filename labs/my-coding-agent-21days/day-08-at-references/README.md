# D8 实验：一套 @ 引用解析与注入链路，带注入量统计与超限裁剪

> 目标：别让 Agent 自己翻遍整个仓库。实现 `@` 引用语法，把文件、目录、网页地址解析成
> 结构化的注入内容，处理二进制与超大文件，并在终端显式打印这一次注入了多少字符、
> 估算多少 token、占引用预算的百分之几。
> 现象最好看的一条：材料贴进来之后，同一个问题**零次工具调用**就给出了结论——
> 而前七天它要 glob、read_file 来回三四轮才能拿到同一份东西。

## 你会学到

- 实现引用解析器，识别文件、目录、网址三类来源，并处理邮箱、转义、空格与中文标点
- 实现展开器，分别产出带行号的文件正文、只有清单的目录树，以及抓取后抽出的网页正文
- 加注入预算与裁剪规则：一级来源宁可截断也要留，二级来源超限时先丢
- 在终端打印本次注入的来源清单、字符数、估算 token 与占预算比例
- 区分「拒绝」与「截断」：差一个数量级就拒绝，差一点才截断

## 验收标准

- [ ] `MOCK=1 SELFTEST=1 pnpm start` 打印 `12/12 通过`
- [ ] 三类引用都被解析并注入，终端打出来源清单：`✔ src/calc.js  252 字符 · 约 86 token`，表头带「占引用预算百分之几」
- [ ] `@src/` 只注入文件清单，一个字节的文件内容都没有；`@**/*.js` 展开成多个来源并标成通配符展开
- [ ] 不存在、二进制、超大、通配符没命中四种情况各有一行人话提示（带 ✘），并且都不注入
- [ ] 材料注入之后那一轮**零次工具调用**就给出结论，而且消息数组里是「注入一条 + 用户原话一条」两条

## 常见坑

- **邮箱不是引用。** 判据是「@ 必须在开头或者紧跟空白」，不是「文本里有没有 @」。少了这一条，用户每写一次邮箱地址，Agent 就去读一个不存在的路径并报一次错。
- **中文标点是硬终止符，ASCII 的点不是。** `看看 @src/calc.js。还有…` 里那个句号必须停下解析；但 `.` 不能当终止符，`calc.js` 自己就带一个点。斜杠两张表都不进——它是目录的标记。
- **目录只给文件树，不给内容。** 目录是「范围」不是「材料」。把一个目录的内容全塞进去，是把预算换成噪音，而且挤掉的往往正是用户明确点名的那个文件。
- **超大文件拒绝，不要截断。** 截断一个日志，模型拿到首尾各一段，而中间那句关键报错正好在被截掉的地方——它看不出自己被骗了，会基于不完整的材料给出很自信的结论。拒绝并给出下一步（用 `read_file` 带 offset 分段读），反而让它能拿到真正需要的那一段。
- **单源上限那里可以截断**，因为那是已经通过大小检查的文件，量级可控，而且截断处会写清「中间截掉了多少、怎么补读」。两种处理的分界线是「差一点」还是「差一个数量级」。
- **一级来源永不静默丢弃。** 用户明确点名的东西宁可截断也要留一段并说清截了多少；预算不够时丢的是通配符与目录带出来的二级来源，从最后一条开始丢，而且丢了也要报数。
- **注入内容要单独一条消息，别拼进用户那句话里。** 拼在一起会有三个损失：模型不再引用用户写的那个 @ 名字、用户翻历史看不到自己说过的话、第十二天压缩时只能整条丢。
- **报账打在终端，不打给模型。** 「注入了多少字符、约多少 token」是给人做决策用的，塞给模型只是浪费预算——和第三天 `ToolResult.meta` 不回灌是同一个道理。
- **token 估算一定不准。** 这里的中英分系数只求一个量级，真正的计数要靠 tokenizer。第十二天会用网关回传的真实用量把它校准。
- **正文提取要先整块删 `script` 与 `style`，再把标签换成空白。** 顺序反过来，脚本代码会变成正文。抽不出正文（前端渲染的页面）时要降级并说清楚，不要硬猜。
- **抓网页三件套一个都不能省**：超时、大小上限、内容类型检查。没超时会把一轮对话挂在一个不响应的服务器上；没大小上限，一个几十兆的页面在你算预算之前就已经进内存了。
- **注入的资料要明确标成「资料不是指令」。** 网页正文与仓库文件都可能含有「请忽略之前的指令」这类文字，注入消息的开头那句声明是最低成本的一道防线。
- **总预算怎么在各路之间分配不是今天的题目**（那是第十二天）。今天立的纪律只有一条：每一路注入都要自己报账。
