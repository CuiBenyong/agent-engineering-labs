# D19 实验：把图片接进消息结构，照着截图改代码

> 目标：让 `mca` 看得见。今天**不引 sharp、不引 jimp、不引 image-size**——
> 图片的格式嗅探、尺寸解析、体积校验、base64 编码全部自己写；连演示图片都是代码
> 现拼出来的（`vision/png.ts` 手写了一个最小 PNG 编码器），**仓库里一个二进制文件都没有**。
>
> 现象最好看的两条：贴一张 `@work/shots/ui.png` 进去，模型先 `read_file` 再
> `edit_file`，沙盒仓库里那份文案真的从「提交」变成了「保存并提交」；
> 以及一张 4x4 的图**在发出去之前**就被拦下，给出的是一句人话而不是网关错误码。

## 你会学到

- 为什么第一天就把 `Message.content` 定成 `string | ContentPart[]`：今天要改的**只有出口那一层**
- 终端里根本没有「粘贴一张图片」这回事——能到达进程的只有文本，所以来源只有路径与 data URL 两条
- 图片引用为什么必须**排在 `@` 展开之前**：一个 `.png` 走第八天那条路会注入一坨乱码
- 格式要**看魔数不看扩展名**，以及 JPEG 的宽高为什么必须沿着 marker 走
- 尺寸下限为什么要在客户端就拦（实测 4x4 被判无效、64x64 正常）
- 一张图在报文里到底有多大：字节数、base64 字符数，以及为什么**不换算成花费金额**
- **不支持图片的模型不会报错，它会编一个答案**——所以能力探测必须用可验证的判据
- 探针图为什么要自己生成、颜色为什么要随机：答案已知，判据才能被独立核对
- 降级要说「我看不见」，不能默默按猜测干活
- 图片不该原样进会话日志，也不该被重放进压缩摘要——两个出口，两种投影

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env

# 验收入口：全课二十一天统一用这一条
MOCK=1 SELFTEST=1 pnpm start

# 主现象一：贴一张截图，照着它改仓库里的文案
rm -rf work
printf '照着这张截图把工具栏的主按钮文案改一下 @work/shots/ui.png\ny\n/exit\n' | MOCK=1 pnpm start

# 主现象二：小于下限的图在发出去之前就被拦下，给的是人话
rm -rf work
printf '看看这张 @work/shots/ui-tiny.png\n/exit\n' | MOCK=1 pnpm start

# 主现象三：名字叫 .jpg，字节是 PNG —— 按字节判，报文里写的 mediaType 才是对的
rm -rf work
printf '这张呢 @work/shots/screenshot.jpg\n/exit\n' | MOCK=1 pnpm start

# 主现象四：账本。收什么格式、下限多少、单张与单轮上限是多少
rm -rf work
printf '/vision\n/exit\n' | MOCK=1 pnpm start

# 只有这一条需要真实 key：真的发一张答案已知的探针图出去，核对它答得对不对
printf '/vision probe\n/exit\n' | pnpm start
```

> **哪些数字可复现：** `MOCK=1 SELFTEST=1 pnpm start` 打印的每一项都可复现（连跑两次
> diff 为空）：图片的宽高、字节数、base64 字符数、被拦下的原因、日志字节数。
> 演示图片是用坐标算出来的确定性噪点拼的，**没有用随机数**，所以同一台机器上两次生成
> 的字节完全一样。今天**不需要网络、不占任何端口**。
>
> **哪一件事这里验不了：模型到底看没看见那张图。** 离线剧本里「模型看见了什么」是
> 写死的台词，自检第十五项证明的是链路通了、文件真的按图改了，不是它有视力。
> 要验视力只有一条路：去掉 `MOCK=1`，用真实 key 跑 `/vision probe`。

> `pnpm install --ignore-workspace` 可能以非 0 退出并打印 `Ignored build scripts: esbuild`，
> 这不代表安装失败——看 `node_modules` 有没有生成、`pnpm typecheck` 过不过就够了。

- [ ] JPEG 那一项：走过一段霍夫曼表之后读到 200x120（不跳过 `C4` 的话这里会读出一个离谱的数，而且不报错）
- [ ] 下限那一项：4x4 被拦下，提示里说清了「多大、合格线、下一步」三件事

- [ ] 粘贴那一项：十七万字符的 data URL 被摘走，正文只剩一个 `[截图 1]`

- [ ] 日志那一项：十七万字符的 base64 没进 jsonl，整个会话日志比它还小

## 常见坑

- **不要按扩展名判断格式。** 截图工具存成 `.jpg` 实际是 PNG 是很常见的一件事，而 `mediaType` 是要写进报文的。写错了对面要么回一个看不懂的错，要么把它当坏数据丢掉——两种都很难查。魔数是文件自己带的，它才是事实。
- **JPEG 解析不要跳过 `C4` / `C8` / `CC` 这条判断。** 它们的编号落在 `C0`–`CF` 这个 SOF 区间里却不是 SOF。漏了这条，你会把霍夫曼表里的字节当成宽高读出来，**而且它不会报错**，只会给你一个离谱但形状正常的尺寸。
- **图片引用必须排在 `@` 展开之前。** `@work/shots/ui.png` 在第八天那套语法里就是一个普通的文件引用，展开出来是一坨乱码。正确做法是先把图片那几条摘走，再在原文里把它们**转义**掉（`\@`）交给 `@` 那一层——转义是第八天就有的机制，本来就是为了表达「这个 @ 别当引用」。
- **粘进来的 data URL 不能留在用户那句话的正文里。** 一张 125 KB 的图 base64 之后是十七万字符，留着的话终端刷屏、会话日志爆炸、压缩摘要里塞满 base64。摘出来换成 `[截图 1]`，模型看到的是占位符加一张真图，正好对得上。
- **不要把 `content` 一律改成数组。** 两种写法对面都认，但改成数组会让每一条历史消息的字节形状都变一遍，而提示缓存是按前缀命中的。纯文本消息保持字符串，只有真的带图那一条才用数组。
- **不要靠「没报错」判断模型支不支持图片。** 2026-09-07 实测：一个不支持视觉的模型把一张纯红图说成了蓝绿色，全程没有任何错误。也不要靠模型 id 里有没有 `vision` 字样——模型 id 的形状随网关变（第一天讲过），更不要维护一张自己的支持清单，**清单过期时没有任何东西会报错**。唯一靠谱的判据是「发一张答案已知的图，核对它答得对不对」。
- **探针图的颜色要随机换。** 固定一种颜色时，一个瞎蒙的模型有不小的概率蒙对，而你会因此把它判成支持。
- **离线剧本模式下不要做能力探测。** 剧本是写死的台词，拿它探能力什么都测不出来，只会把一场好好的离线演示判成「模型看不见」。
- **降级的那段说明里不要替模型描述图里有什么。** 我们自己也没看，写出来就是编。只说我们真的知道的事（格式、尺寸、来自哪里），然后明确要求它说「我看不见」并向用户要文字描述。
- **照图改代码要先 `read_file` 再 `edit_file`。** 直接让模型按图里的样子写文件，它会连图上看不见的部分一起改掉——改动范围应该由原文决定，不是由那张图决定。
- **图片不要原样写进会话日志。** 代价要一起说清：**恢复出来的会话里没有那张图了**。这是有意的取舍——截图是一次性输入，它的结论已经变成了后面的对话与真实的代码改动；真要再看一眼，原图还在 `work/shots/` 里，重新 `@` 一次就是了。
- **先 `seedRepo` 再 `seedDemoShots`。** 反过来的话沙盒仓库的重建会把界面文案那个文件冲掉，而表现是「模型说找不到 src/ui.js」，跟图片一点关系都没有。
- **上限那几个数字是我们自己定的本地策略，不是任何一家网关的上限。** 各家对图片大小、边长、张数的限制不一样而且会变，代码里写死一个别家的数字，等于埋一个会悄悄过期的假事实。`/vision` 的输出里把这句话原样打了出来。
