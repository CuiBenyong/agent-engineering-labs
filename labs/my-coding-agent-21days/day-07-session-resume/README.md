# D7 实验：可恢复、可分叉的会话事件日志与一次跨进程接着干的完整演示

> 目标：让对话不再随进程消失。一份只追加的 JSONL 事件日志记下每条消息、每次工具调用与每次用量，
> 重启之后 `--resume` 重放日志把现场搬回来，还能从任意一个干净的边界分叉出一条新会话。
> 现象最好看的一条：第一个进程查明「失败的是 divide by zero 那个用例」，
> 退出；第二个进程带 `--resume` 起来，第一句话就是「按上一轮查到的，给 divide 加上除零保护」。

## 你会学到

- 设计一份只追加的会话事件日志，并说清为什么不存快照式的会话对象
- 让日志边跑边落盘，顺序天然是「助手消息 → 它的 tool_end → 工具结果消息」
- 通过重放事件恢复会话，并处理「最后一行写到一半」这个常态
- 从任意一个干净的边界分叉出新会话，并说清分叉与回滚的区别
- 自检里跑完写入、跨进程恢复、日志损坏、分叉四条路径

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env

# 验收入口：全课二十一天统一用这一条
MOCK=1 SELFTEST=1 pnpm start

# 第一轮：查明失败的是哪个用例，然后退出
printf '跑测试看看哪个用例失败了\n/log\n/exit\n' | MOCK=1 pnpm start

# 第二轮：换一个进程接着干（注意它第一句就引用了上一轮的发现）
printf '那把它修掉\ny\n/fork\n/exit\n' | MOCK=1 pnpm start --resume

# 列出会话；--resume 也可以指定 id
MOCK=1 pnpm start --sessions
MOCK=1 pnpm start --resume=s-20260907-103250-xxxx

# 分叉：在 REPL 里 /fork 不带参数看可选位置，/fork 8 就从第 8 条事件分出去
```

> `pnpm install --ignore-workspace` 可能以非 0 退出并打印 `Ignored build scripts: esbuild`，
> 这不代表安装失败——看 `node_modules` 有没有生成、`pnpm typecheck` 过不过就够了。

> **会话 id 里带日期时间，所以它不可复现。** 上面命令里的 `s-20260907-103250-xxxx` 只是形状示例，
> 跑一次 `--sessions` 看你自己的那个。事件条数与 seq 是可复现的（`MOCK=1` 下剧本固定），
> 但每行的 `ts` 与会话 id 不是。

## 常见坑

- **别存「会话对象」。** 把整个会话序列化成一个 JSON 存下来，每轮改一次，看着最省事：代价是每次都要整体读、整体写，而且任何一次崩溃都可能让你拿到一个语法合法、语义错乱的文件。只追加的失败模式只有一种——最后一行不完整——所以它是唯一你能事先想清楚的那种。
- **最后一行写坏是常态，不是异常。** 进程随时会被 Ctrl+C、被 kill、被关掉终端。读到坏行就停在前一行，不跳过、不修补：跳过它继续读，等于假设文件中间也会坏，而追加写不会产生那种情况。
- **只有 message 事件参与重建消息数组。** `tool_end` 里也有工具结果，但那条结果**已经**以一条 role 为 tool 的消息记过了；`tool_end` 额外记的是耗时、字符数、是否截断、被谁挡下来，那些是给人看的。两类信息混在一种事件里，第十二天做压缩时就要在同一个对象上区分「这部分发给模型」和「这部分只给人看」。
- **边跑边落盘，不要攒到一轮结束。** 顺序会错（日志变成先事件后消息），而且中途被杀掉时那一轮一条都不剩。
- **消息落盘按「数组长度差」来做，不要在每个 push 的地方各加一行记录。** 循环里往消息数组 push 的位置有五处，早晚漏一处。
- **分叉是复制到新文件，不是原地截断。** 原地截断是一次改写，写到一半崩了会同时失去母会话和分叉。分叉的语义是「从这里长出一条新的」。
- **分叉点不是任意一行。** 只有用户消息与不带工具调用的助手消息之后才是干净边界。在带工具调用的助手消息之后截断，会得到一个「请求了工具却没有结果」的消息数组，下一轮请求直接不合法。
- **分叉的 seq 不重新编号。** 保留原编号，才能拿分叉点的 seq 直接对回母会话；重编号之后血缘就只能靠 `fork` 事件里的那个数字了。
- **恢复不等于「它记住了」。** 模型依然没有记忆，只是历史被从磁盘搬回了消息数组。所以恢复之后终端一定要打一行「重放了多少条」——不然用户分不清它是记得，还是在瞎猜。
- **`--resume` 不带 id 取「最近一个」，别去维护一个「当前会话」指针。** 那个指针和实际文件一旦不一致，表现是「resume 到了一个空会话」，很难查。会话 id 里带时间，排序即最近。
- **今天的日志和 D14 的快照是两件独立的东西**：日志恢复对话，快照恢复文件。可以只回滚一边，这一点到第十四天会反复用到。
