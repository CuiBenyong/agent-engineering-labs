# D3 实验：读文件、找文件、搜内容三个只读工具与一套带截断的工具执行链路

> 目标：给 Agent 装上眼睛。今天它第一次能自己决定「先看有哪些文件、再搜一个函数名、再读那段实现」，
> 并在读到一个太大的文件时把结果截断、把「截掉了多少」老实告诉模型。
> 工具 schema 的写法、流式工具调用分片的归并、结果截断这三件事今天一次定清楚，后面十八天都靠它。

## 你会学到

- 定义工具注册表与统一的执行入口，让循环不必认识每个工具
- 实现读文件、找文件、搜内容三个只读工具，各自带参数校验与限量
- 按序号归并流式工具调用分片，并用故障注入喂一段非法参数验证回灌
- 给工具结果加截断，超限时保留首尾并注明截掉的字符数
- 自检里让离线剧本连续调用三个工具，断言调用顺序与截断结果

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env

# 验收入口：全课二十一天统一用这一条
MOCK=1 SELFTEST=1 pnpm start

# 看它自己用三个工具读懂沙盒仓库
printf '帮我看看这个仓库，测试为什么红\n/tools\n/exit\n' | MOCK=1 pnpm start

# 看非法参数被回灌纠正（不是崩）
printf '帮我看看这个仓库\n/exit\n' | MOCK=1 INJECT=bad_args pnpm start

# 看它编了一个还不存在的工具时会怎样
printf '改一下 divide\n/exit\n' | MOCK=1 pnpm start
```

> `pnpm install --ignore-workspace` 可能以非 0 退出并打印 `Ignored build scripts: esbuild`，
> 这不代表安装失败——看 `node_modules` 有没有生成、`pnpm typecheck` 过不过就够了。

## 验收标准

- [ ] `MOCK=1 SELFTEST=1 pnpm start` 打印 `7/7 通过`
- [ ] 问一句「帮我看看这个仓库」，终端上依次出现 glob、grep、read_file 三张工具卡片，最后是结论
- [ ] 交错到达、序号从 1 开始的分片能归并成两个调用，参数拼接后是合法 JSON
- [ ] 20000 字符的结果被截到 8054 字符（8000 的上限加那行说明），并写明截掉了 12000 字符
- [ ] `INJECT=bad_args` 时终端出现「参数不是合法 JSON」，循环继续往下走且退出码是 0

## 常见坑

- **不要假设工具调用分片的序号从 0 开始。** 2026-09-07 实测同一个模型在同一家网关上的两次运行，两个并行调用的序号起点分别是 1 和 2、以及 0 和 1。所以归并必须按序号建字典；按到达顺序 push 进数组更错，因为并行调用的分片是交错到达的。本实验的离线剧本故意让序号从 1 开始。
- **参数拼起来才是合法 JSON，解析失败是常态。** 它不该抛异常，而该变成一条 ok 为 false 的工具结果回灌给模型，并带上原文的前一段——模型看到自己写坏在哪就会重发。抛出去的后果是整个 REPL 带着堆栈退出。
- **每个工具调用必须有且只有一条对应的 tool 消息。** 失败也要追加，少一条下一轮请求就不合法，大多数网关会直接报错。助手消息也必须带上它请求的那些调用，否则工具结果指不回去。
- **截断要从中间截，不能只留头。** 尾部往往有结论性的信息（报错的最后一行、测试的汇总行）。而且必须告诉模型截掉了多少、下一步怎么拿中间那段——模型看不懂省略号，但看得懂「用 offset 继续读」。
- **路径边界要用解析后的绝对路径判断。** 在字符串里查两个点不可靠（软链接、编码都能绕过）。判据是「解析成绝对路径之后还在不在工作目录里面」，而且比较前记得给根目录加一个分隔符，否则同前缀的兄弟目录会被误判成在里面。
- **`grep` 的正则不要带全局标志。** 带 `g` 的正则对象在多次调用 test 时会记住上一次的位置，逐行匹配的结果会随机漏掉一半。
