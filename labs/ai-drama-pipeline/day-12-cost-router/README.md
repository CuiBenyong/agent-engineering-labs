# D12 实验：按环节分档的模型路由与带预算熔断的成本面板

> 目标：把一集短剧的账彻底摊开——按环节看钱花在哪，用草稿档与成片档两套路由做取舍，用缓存把重跑的花费压下去，再给整次运行装一个真的会踩刹车的预算熔断。做完你会亲眼看到：这条线上九成以上的钱都在视频生成那一步，其余环节怎么优化都是零头。

## 你会学到

- 统计一次完整运行里各环节的调用次数与花费，画出成本结构
- 实现草稿档与成片档两套路由，用同一句输入分别跑一遍并对比成本与质量
- 给可缓存的环节加上缓存，重跑同一集验证花费显著下降
- 实现软硬两级预算熔断，超过硬上限时安全停机并保留已完成产物
- 输出成本面板，按环节与按 provider 两个维度展示

## 目录

- `starter/`：挖了 5 个练习的起始代码，`MOCK=1` 下可以直接跑
- `solution/`：参考答案
- `src/providers/`、`src/ffmpeg.ts`、`src/run.ts`、`src/dag.ts`：**来自 D1，本天不改**（每个 lab 独立，不跨 lab import）
- `src/pricing.ts`：明码标价表、成本台账、成本面板
- `src/router.ts`：草稿档与成片档、三个可降级维度
- `src/cache.ts`：内容寻址的产物缓存
- `src/budget.ts`：软硬两级预算熔断

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env  # 填 MINIMAX_API_KEY；没有 key 先用 MOCK=1
MOCK=1 pnpm start     # 离线模拟，正常路径（阶段 ① ② ③ ④ ⑥）
INJECT=overbudget,blocked MOCK=1 pnpm start   # 再跑一次，把两个故障注进去
WORK_DIR=~/drama-out pnpm start            # 真实厂商（产物写仓库外：花过钱的素材别放临时目录）
```

### 故障注入：`INJECT`

本课所有「人为制造一次失败」的地方都用同一个环境变量 `INJECT`，值是逗号分隔的场景名。
本天支持两个：

| 值           | 效果                                                                        |
| ------------ | --------------------------------------------------------------------------- |
| `overbudget` | 把硬上限压到 ¥3 再跑成片档，演示熔断与安全停机（阶段 ⑤）                    |
| `blocked`    | 让 s02 的第一次视频生成命中安全审核，演示「失败不扣费」的台账口径（阶段 ②） |

注入只作用在计费与 provider 出口，业务逻辑（路由、缓存、预算、降级）照常执行。

> 说明：`starter/` 与 `solution/` 都不属于仓库根 pnpm workspace（根 `pnpm-workspace.yaml` 只包含
> `apps/*`），`pnpm install` 时要加 `--ignore-workspace`。

### 一个必须先说清的前提：这里的金额全是估算

`MOCK=1` 下没有真的调用厂商，provider 返回的 `costCny` 恒为 0。所以面板上的每一笔钱，
都是 `src/pricing.ts` 里的单价乘以本次的 units 算出来的**估算值**，用于教学与容量规划，
**不能当对账依据**。三档单价的可信度并不一样：

| 项目             | 可信度                                                                                                                                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 图像 ¥0.025 / 张 | 官方按量付费页直接标价，可以当真                                                                                                                                                                             |
| 视频按秒         | 付费页给的是 768P ¥0.50、2K ¥0.80、480P ¥0.33 三个**档位**的按秒单价；本课用的视频接口在官方走**视频点数**扣减、没有公开按秒单价，两套口径不通用，所以表里这几行是**台账演示用的折算常量**，`approx` 为 true |
| 语音按字符       | 官方只公开资源包价，这是折算值，`approx` 为 true                                                                                                                                                             |
| 文本             | 干脆不计价，只统计 token，单价以官方控制台为准                                                                                                                                                               |

所以这张表按「档位 + 规格」计价，**不挂到任何具体模型 id 上**。做成本台账的第一件事，
就是搞清楚每一项到底按什么计价——这条比表里的数字本身更值得记住。

## 验收标准

1. `MOCK=1 pnpm start` 跑完六个阶段，草稿档与成片档各打印一张成本面板，两张面板里 `clips`（视频）那一行都超过总额的 95%
2. 阶段 ③ 原样重跑时打印「缓存命中 11 / 11 条」，本次新花费为 ¥0.0000
3. 阶段 ④ 只改 s02 的画面描述后重跑，打印「缓存命中 9 / 11 条」，新花费只有被改动的那一镜的首帧与视频
4. 用 `INJECT=overbudget` 重跑，阶段 ⑤ 日志里出现「✋ 硬上限熔断」，且随后打印「已完成产物 5 个仍在磁盘上」——停机之后产物没有被删，缓存也写进去了
5. 阶段 ⑥ 预算 ¥5 时先打印采纳与跳过的降级步骤，再按降级后的计划跑完，总额落在 ¥5 以内
6. 用 `INJECT=blocked` 重跑，面板里出现「失败/被拦截未计费」一行：被安全审核拦下的那次视频生成记了账，但没有计费

## 常见坑

1. **把熔断写成事后统计。** 「跑完发现超支」没有任何意义，钱已经花出去了。必须在每次要花钱之前 `reserve()` 一次，扣不动就不发这个请求。
2. **失败的视频也照算钱。** 生成失败或命中安全审核的视频不扣费，台账要记一条 `billed: false` 的行，并把预扣的预算退回去，否则你会一边高估账单一边白占预算。
3. **缓存键把时间戳或 runId 拌了进去。** 那样每次跑出来的键都不一样，缓存永远不命中，面板上「缓存命中 0 / 11」是唯一的症状——它不报错，只是默默不省钱。
4. **降级降在了不省钱的维度上。** 单价表里没有 512P 这一档，我们按 768P 往贵了估，于是「降清晰度」在账面上一分钱都省不出来。降级要看账，不能凭感觉；`degradeToFit` 里那一段「省不出钱就跳过」不是防御性代码，是正经判据。
5. **熔断时直接 `process.exit(1)`。** 那会丢掉本次的账本与进度文件，下次只能从头再来——安全停机的定义就是「产物留着、账记完、下次能接着跑」。
