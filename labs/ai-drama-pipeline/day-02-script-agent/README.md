# D2 实验：一句话生成整集分镜数据的剧本 CLI，带评审打磨循环

> 目标：让模型输出的不是一段散文，而是一份**程序能直接消费**的剧本数据——世界观档案、人物卡、
> 整集分镜——并且加一个评审角色，用一张可判定的评分表把稿子在循环里改到达标才停。
> 这份 JSON 里的每一个字段，后面十二天都要吃：`visual` 进图像提示词、`camera` 进视频提示词、
> `dialogue` 进配音、`durationSec` 进时间轴。

## 你会学到

- 定义人物卡、场景、分镜三类数据的 schema，并让模型按 schema 输出
- 实现写手与评审两个角色，评审按固定评分表给分并指出具体问题
- 让循环在评分达标或达到次数上限时停下，并把每一轮的稿子都留档
- 把人物与世界观抽成单独的档案文件，供后续所有天读取
- 换三句不同的一句话输入，确认产出的分镜数据结构稳定、字段不缺

## 目录

- `starter/`：挖了 4 个编号练习的起始代码，`MOCK=1` 下可以直接跑（但跑出来的稿子有明显毛病）
- `solution/`：参考答案

两边的 `src/` 结构相同：

```text
src/
├── index.ts            CLI 与写手评审循环的编排（当天真正要读的部分）
├── schema.ts           手写的 schema 校验与 JSON 抠取
├── writer.ts           写手：拼提示词、要 JSON、校验不过带着问题重来
├── review.ts           评审：硬伤用代码查，软伤交给模型打分
├── offline.ts          MOCK=1 时替换文本 provider 的离线剧本实现
├── run.ts              来自 D1，本天不改
├── ffmpeg.ts           来自 D1，本天不改（今天不生成媒体，但 providers 依赖它）
└── providers/          来自 D1，本天不改
```

**今天不需要装 ffmpeg**，也不会调用图像 / 视频 / 语音接口——只用到四类 provider 里的文本那一类。

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env  # 填 MINIMAX_API_KEY；没有 key 就一直用 MOCK=1
MOCK=1 pnpm start                                  # 离线，用默认的一句话
MOCK=1 pnpm start "退休法医在菜市场认出了通缉犯"      # 离线，换一句话
INJECT=badref MOCK=1 pnpm start                    # 离线写手故意产出一份引用错乱的坏稿
WORK_DIR=~/drama-out pnpm start "你的一句话"        # 真实模型（要 key，产物写仓库外）
```

可调的两个环境变量：`PASS_SCORE`（达标线，默认 88）、`MAX_ROUNDS`（轮数上限，默认 4）。

产物在 `work/runs/<runId>/script/` 下：`world.json`、`characters.json`、`episode-1.json`，
以及 `drafts/round-N.json` 与 `drafts/round-N.review.json`（每一轮的稿子与评语，可以 diff 着看改了什么）。

## 验收标准

1. `MOCK=1 pnpm start` 跑完，写手评审循环打印出**逐轮上升**的分数（参考实现是 69 分、86 分、91 分），并在达标那一轮停下，不跑满 4 轮。
2. 每一轮的硬伤条数逐轮减少，且每条硬伤都带 `[camera]` `[duration]` `[dialogue]` 这类分类前缀。
3. 定稿的 `episode-1.json` 里，所有分镜都有非空 `camera`、时长都在 3 到 8 秒之间。
4. `INJECT=badref MOCK=1 pnpm start` 会打印「schema 不过 2 处，带着问题重来一次」，然后正常跑完——坏稿被拦住并修好了，不会进 `episode-1.json`。
5. 换三句不同的一句话跑，`world.json` / `characters.json` / `episode-1.json` 的字段一个不缺，但内容（音色 id、场景名、分镜条数）真的跟着变。

`starter/` 原样跑时第 1、2、3、4 条都不达标：分数四轮都是 90、跑满上限、定稿里留着一个 12 秒的镜头和一句 40 字的台词、坏稿一路放行。四个编号练习分别对应这些症状。

## 常见坑

1. **模型不会只给你 JSON。** 它会加寒暄、加解释，或者用 ```json 围栏包起来。所以必须有一个「抠 JSON」的步骤：找第一个花括号或方括号、找最后一个配对的收尾符号，中间那段才拿去解析。直接 `JSON.parse(整段回复)` 在真实模型上十次有三次会炸。
2. **判类型挡不住写错对象。** 字段类型全对、但 `sceneId` 指向一个不存在的场景，这种稿子能通过一个只判类型的校验，然后在第 3 天生成场景图时才爆。引用完整性检查（角色 id、场景 id、镜号唯一）必须单独写一遍，这就是 `INJECT=badref` 要演示的东西。
3. **能被程序判定的，绝不要交给模型评。** 时长超没超、台词多少字、镜号重没重复，代码一行就查完，还不花钱、结论稳定；交给模型评你会得到一个随机波动的分数。模型只该评它独有的那部分：钩子、动机、结尾留不留人。
4. **循环一定要有两个出口。** 只有「达标才停」的循环会在评分标准写太严时烧完你的配额；只有「跑满 N 轮」的循环会在稿子早就够用时白花三轮钱。两个出口都要有，并且跑满上限时要明确告诉使用者「这是没达标的稿子，该人工拍板了」。
