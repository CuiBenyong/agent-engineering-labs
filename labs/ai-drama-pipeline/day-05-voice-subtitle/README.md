# D5 实验：按角色批量配音并产出对齐字幕文件的配音环节

> 目标：让每个角色说自己的声音，用量出来的真实音频时长反过来校正镜头时长，再由这条时间轴生成一份时间码连续不重叠的字幕文件——这一天定下的时间轴，就是 D6 剪辑台唯一的输入。

## 你会学到

- 为每个角色分配音色，批量合成本集全部台词并落盘
- 读取每段音频的真实时长，回写进分镜数据，标出与原定时长冲突的镜头
- 按对齐后的时间轴生成字幕文件，并用自检确认时间码没有漂移
- 把人声、环境音、背景乐的响度关系写成一份混音计划，交给 D6 去落成命令
- 在离线模式下用占位音频跑完同一条路径，确认时长对齐逻辑仍然执行

## 目录

- `starter/`：挖了四个练习的起始代码，`MOCK=1` 下可以直接跑
- `solution/`：参考答案
- `src/providers/`、`src/ffmpeg.ts`、`src/run.ts`：**来自 D1，本天不改**。语音走 D1 的 `TtsProvider`
- `src/voice.ts`：音色分配表与批量合成
- `src/timeline.ts`：时长校正、时间轴与字幕 cue、SRT 生成与三项自检、混音计划
- `src/index.ts`：五步串起来，最后一步把所有时间码问题列成清单

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env  # 填 MINIMAX_API_KEY；没有 key 先用 MOCK=1
MOCK=1 pnpm start     # 离线占位，零外部依赖
WORK_DIR=~/drama-out pnpm start   # 真实调用语音合成接口（产物写仓库外）
```

> 说明：`starter/` 与 `solution/` 都不属于仓库根 pnpm workspace（根 `pnpm-workspace.yaml` 只包含
> `apps/*`），`pnpm install` 时要加 `--ignore-workspace`。
> 占位音频靠 ffmpeg 生成，时长也靠 ffprobe 量：macOS 用 `brew install ffmpeg`，Debian 用 `sudo apt-get install -y ffmpeg`。

产物：`work/runs/<runId>/shots/<镜号>/voice-N.mp3`、`timeline/episode-1.json`、`output/episode-1.srt`。

## 验收标准

1. 第 1 步的分配表里两个角色是**两个不同的音色 id**，且与人物卡里的 `voiceId` 一致。
2. 第 2 步每条台词打印出的时长来自落盘文件（离线模式下与估算值恰好相等，接上真实接口会出现偏差——那个偏差正是必须读真实值的理由）。
3. 第 3 步 `s02` 被标成「台词装不下，已顶长」，且 `script/episode-1.json` 里它的 `durationSec` 已经被改成校正后的值。
4. 第 5 步打印 `✅ 未发现问题`：镜头首尾相接、字幕不重叠、每条字幕都落在自己那一镜里、时间码格式合法。
5. `pnpm typecheck` 通过，没有 `any`。

## 常见坑

- **拿估算时长建时间轴**：字数乘一个系数只能用来排期。真实语音受语速、情绪、标点停顿影响，差个几百毫秒很正常，而字幕漂移是逐句累加的——第一句差 200ms，到第十句就差两秒。时长必须从落盘文件量。
- **只改字幕不改镜头**：台词说不完时把字幕压短，观众会看到嘴还在动、字已经没了。本课的口径是台词优先，把镜头顶长，并把这一镜标成待人复核。
- **SRT 时间码用句点**：`00:00:01.320` 是 WebVTT 的写法，SRT 要用逗号，而且时分秒必须补零。写错了播放器往往不报错，只是一条字幕都不显示。
- **一行字幕太长**：竖屏宽度有限，超过十来个汉字就会糊满屏幕。断行优先找标点，硬断很容易在第二行留下一个孤字。
- **背景音乐随手拿来用**：BGM 的版权是这条流水线上最容易翻车的地方，比任何技术问题都严重；同理，不要用真实人物的声音或形象。相关的合规做法在 D11 展开。
