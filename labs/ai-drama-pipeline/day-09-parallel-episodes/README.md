# D9 实验：按 provider 限流、支持优先级的并行生产队列

> 目标：把「一次只做一集」改成「六集同时开机」，同时保证对每家厂商的压力不超过它给你的配额——
> 队列、令牌桶、优先级、退避、长任务不占槽，五件事一次跑通，并用日志逐条证明它们真的生效了。

## 你会学到

- 实现按 provider 分桶的并发闸门与令牌桶限流
- 让五集同时进入队列，观察各 provider 的实际并发是否被限住
- 注入限流响应，验证退避策略生效且任务最终成功
- 加入优先级队列，插入一条急稿并确认它抢先且没有饿死其他任务
- 把长任务的等待改成不占用工作槽，用日志证明槽位被释放

## 目录

- `starter/`：挖了 5 个练习点的起始代码，`MOCK=1` 下可以直接跑（跑出来会有 5 项是 ❌）
- `solution/`：参考答案，`MOCK=1` 下 6 项全 ✅
- `src/limiter.ts`：闸门（令牌桶 + 并发信号量），本天的重点之一
- `src/queue.ts`：调度器与工作槽池，本天的重点之二
- `src/jobs.ts`：把一集展开成带依赖的若干任务
- `src/providers/`、`src/ffmpeg.ts`、`src/run.ts`、`src/dag.ts`：**来自 D1，本天不改**

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env  # 填 MINIMAX_API_KEY；没有 key 先用 MOCK=1
MOCK=1 pnpm start                        # 正常路径，离线跑，零外部依赖，约十几秒
INJECT=ratelimit MOCK=1 pnpm start       # 注入限流：前 1 次图像、前 2 次语音返回 status_code=1002
WORK_DIR=~/drama-out pnpm start                               # 真实厂商（产物写仓库外：花过钱的素材别放临时目录）
```

本天支持的 `INJECT` 取值只有一个：

| 取值        | 效果                                                                      |
| ----------- | ------------------------------------------------------------------------- |
| `ratelimit` | 前 1 次图像调用与前 2 次语音调用返回 `1002`，用来验证退避、降档与最终成功 |

注入只作用在 provider 出口，闸门、调度、优先级、老化这些业务逻辑照常执行。

可以调的旋钮（都有默认值，不改也能跑）：

```bash
WORKERS=1 MOCK=1 pnpm start           # 只留一个工作槽，看排队时间怎么变
RATE_WINDOW_MS=60000 MOCK=1 pnpm start # 用真实的一分钟窗口，体会 10 RPM 有多紧
AGING_MS=200 MOCK=1 pnpm start        # 老化更激进，低优先级更快被救
```

> 演示默认把速率窗口压成 6 秒，好让实验十几秒跑完；**配额数字（RPM）一个都没改**。
> 生产里把 `RATE_WINDOW_MS` 留成 60000 就是真实行为。

## 验收标准

1. 闸门统计里，每个 provider 的「峰值在飞」都不超过它的并发上限。
2. 「令牌拦下」不为 0，说明令牌桶真的按 RPM 挡住过请求（图像的 10 RPM 是四类里最紧的）。
3. `INJECT=ratelimit` 跑一遍：`1002` 被识别成限流，退避后重新入队，最终全部成功，没有任务失败。
4. 第 6 集作为急稿中途插队，日志里能看到它插到已就绪的低优先级任务前面；同时低优先级任务被老化升档，没有饿死。
5. 视频任务提交后打印「释放工作槽去接别的活」，释放次数等于视频任务数。

两条命令下 `solution` 的 6 项核对都是 ✅ 且退出码为 0；`starter` 原样跑会有 5 项是 ❌。

## 常见坑

- **配额等待占着工作槽，等于没有优先级。** 如果在任务内部 `await` 令牌，工作槽会被一批低优先级任务
  堵死，急稿连被调度的机会都没有。本实验的做法是闸门只做**非阻塞准入**，拿不到许可就把任务留在队列里。
- **先取令牌再抢并发票，会白白烧掉配额。** 令牌取出来却挤不进并发上限，这个令牌就浪费了。
  `tryAdmit()` 里的顺序是先并发、后令牌，反过来写在高压下会莫名其妙地少调用很多次。
- **老化不要升进急稿车道。** 让 low 一路升到 urgent，跑上几分钟之后满队列都是急稿，这一档就废了。
  升档上限设成 normal，urgent 永远是留给人工插队的。
- **退避要带抖动。** 五集同时撞限流、又同时按固定间隔醒来，只会原样再撞一次。
  `backoffMs()` 里的 `0.7 + Math.random() * 0.6` 就是干这个的。
- **限流不只要退避，还要降速。** 收到 1002 之后 `bucket.penalize()` 让接下来两个窗口只发一半令牌，
  否则你会一边退避一边继续用超标的速度冲。
