# D11 实验：自动质检与合规标识环节，含不合格镜头的自动打回

> 目标：让流水线自己挑毛病——把「好不好看」拆成一组能打分的检查项，低分镜头自动打回重做、
> 重做几次还不行就停手叫人；同时把内容安全的两道关和生成合成内容标识落进导出环节。

## 你会学到

- 定义一组可打分的质检项，并对每一镜逐项打分
- 把低于阈值的镜头自动打回上一环节重做，并限制重做次数
- 在提示词提交前与成片产出后各加一道内容安全检查
- 在导出环节写入显式标识与文件元数据里的隐式标识，并验证能被读出来
- 输出一份质检报告，列出每一镜的分数、打回次数与最终结论

## 目录

- `starter/`：挖了 4 个练习点的起始代码，跑出来会有 5 项是 ❌
- `solution/`：参考答案，7 项全 ✅
- `src/qc.ts`：检查项与打分、止损判定，本天的重点之一
- `src/safety.ts`：前置与后置两道内容安全检查
- `src/label.ts`：显式标识（能力探测再降级）与隐式标识（容器元数据读写）
- `src/script.ts`：样例剧本、`INJECT=lowscore` 的两处缺陷、SRT 生成
- `src/providers/`、`src/ffmpeg.ts`、`src/run.ts`：**来自 D1，本天不改**（本天用不到 `dag.ts`，没有复制）

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env  # 填 MINIMAX_API_KEY；没有 key 先用 MOCK=1
MOCK=1 pnpm start                       # 正常路径：三镜都合格，走完标识与后置检查
INJECT=lowscore MOCK=1 pnpm start       # 注入质检缺陷：看打回重做与止损
WORK_DIR=~/drama-out pnpm start                              # 真实厂商（产物写仓库外：花过钱的素材别放临时目录）
```

本天支持的 `INJECT` 取值只有一个：

| 取值       | 效果                                                                                                                     |
| ---------- | ------------------------------------------------------------------------------------------------------------------------ |
| `lowscore` | 第二镜台词长到一屏放不下（字幕检查打回，可自动修正），第三镜是多人多手的高风险构图（评审官一直判崩坏，重做到上限交人工） |

注入只改这两镜的输入数据，质检、打回、止损、标识这些逻辑照常执行。前置内容安全检查的那条违规描述是样例剧本自带的，不受 `INJECT` 控制，两条命令下都会被拦。

跑完可以自己验一遍隐式标识：

```bash
ffprobe -v error -show_entries format_tags=comment -of default=noprint_wrappers=1:nokey=1 \
  solution/work/runs/<runId>/output/episode-1.mp4
```

## 验收标准

1. 三镜各打出 5 项分数（4 项本地客观测量 + 1 项模型评审），报告写进 `output/qc-report.json`。
2. `INJECT=lowscore` 跑一遍：台词过长的那一镜被自动打回，修正后重新跑并最终通过。
3. 同一次运行里，高崩坏风险的那一镜重做到上限仍不达标，被标成 `needs-human` 而不是无限重试。
4. 前置检查拦下「和真人明星一模一样」这类描述，打印替代写法并改写后继续跑。
5. 成片 `output/episode-1.mp4` 用 ffprobe 能读出隐式标识 JSON；显式标识按 `drawtext` 能力探测落地（有就烧录，没有就回落字幕轨并打印提示）。

## 常见坑

- **主观项和客观项要分开记账。** 分辨率、音画差、字幕密度、响度是本地量得出来的；
  角色一致性与画面崩坏本地量不了，只能交给视觉模型。把两类混在一起打一个总分，
  出问题时你分不清是模型看错了还是文件真有问题。
- **模型没答上来 ≠ 模型说没问题。** 评审返回的 JSON 解析不出来时必须当作「本项无结论、需人工」，
  绝不能默认放行——这是自动质检最容易埋进去的事故。
- **重做要带上修正动作。** 同样的输入重做十次还是同样的结果。本实验里字幕超限对应「裁剪台词」、
  音画不同步对应「按台词长度回写镜头时长」；找不到修正动作的项，重做就是纯烧钱，应该直接叫人。
- **止损点必须存在。** 没有 `MAX_REDO`，一个永远过不了的镜头能把预算跑光。
- **显式标识别指望 drawtext。** 很多 ffmpeg build 不带 libfreetype，烧不了字。
  程序要先探测能力再降级，并且把「已降级」这件事打印出来，而不是悄悄少做一件合规动作。
- **写了标识一定要读回来。** `-metadata comment=` 写完就当完事，是最常见的假合规。
