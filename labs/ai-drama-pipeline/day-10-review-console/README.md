# D10 实验：可预览、可改词、可重生成单镜的最小审核后台

> 目标：给全自动流水线开一个人能插手的口子——按镜头看图、看片、听配音，改一句台词，
> 只重跑被这句话波及的节点，并且每一次修改都留下能对比、能回滚的版本。

## 你会学到

- 做出按镜头列出图、视频、台词与配音的审核页面
- 实现改台词并触发重生成，页面上能看到该镜进入生成中状态
- 计算并展示一次修改会波及的下游节点，重生成只跑这些节点
- 保留每一镜的历史版本，支持并排对比与回滚到指定版本
- 把审核意见按结构化字段存下来，导出成一份可复用的记录

## 目录

- `starter/`：挖了 4 个练习点的起始代码，自检会有 5 项是 ❌
- `solution/`：参考答案，自检 7 项全 ✅
- `src/model.ts`：节点依赖图与「爆炸半径」计算，本天的重点之一
- `src/store.ts`：版本、回滚、审核意见，本天的重点之二
- `src/server.ts` / `src/ui.ts`：`node:http` 服务与一个手写的单文件 HTML 页面
- `src/fixtures.ts`：样例剧本与接口调用计数器（用来证明重生成到底调了几次接口）
- `src/selftest.ts`：`SELFTEST=1` 时跑的验收脚本
- `src/providers/`、`src/ffmpeg.ts`、`src/run.ts`、`src/dag.ts`：**来自 D1，本天不改**

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env  # 填 MINIMAX_API_KEY；没有 key 先用 MOCK=1

MOCK=1 SELFTEST=1 pnpm start   # 验收入口：自己走完全流程、逐项打勾叉、按结果退出
MOCK=1 pnpm start              # 常驻，浏览器打开 http://localhost:3080 手动审片
```

常驻模式下：改一句台词 → 点「算影响范围」看橙色提示里列出的受影响节点 → 点「重生成受影响节点」
→ 版本列表出现 v2 → 点「回滚到这版」切回 v1，图、片、配音都跟着回去。

本天不需要故障注入，**不支持任何 `INJECT` 取值**——审核台要演示的是人主动改东西，不是系统出错。

> 端口 3080 是本课统一的口径（3000 + 天号，本天天号 80）。被占用就 `PORT=4080 MOCK=1 pnpm start`。

## 验收标准

1. `MOCK=1 SELFTEST=1 pnpm start` 打印 7 项自检，`solution` 全 ✅ 且退出码为 0。
2. 改一句台词，算出的受影响节点恰好是「该镜的配音 + 整集的时间轴」，首帧与视频不在其中。
3. 重生成之后新版本的 `regenerated` 与上一步算出的半径完全一致，且**图像与视频接口一次都没被调用**。
4. 没被波及的镜头版本号不变；被改的那一镜出现 v2。
5. 回滚到 v1 之后台词与配音都回到旧版本，v2 的产物仍在磁盘上，可以再切回去。

## 常见坑

- **把「改」和「生成」做成同一个动作，会烧掉你很多钱。** 人在输入框里每敲一个字都触发重生成是灾难。
  本实验把修改只登记成草稿（`pending`），生成必须由人再点一次。
- **爆炸半径要正向传播，不是反向。** 常见错误是从被改的节点往上游找依赖，
  结果把没受影响的上游也重跑了。正确方向是「谁依赖我」，从种子沿着出边扩散。
- **版本不是备份。** 备份只保留一份「上一次好的」，版本要求两个都在、随时能并排对比。
  所以产物按 `v1/` `v2/` 分目录存，回滚只是把 current 指针挪回去，一个文件都不删。
- **离线模式下，同样的提示词会生成逐字节相同的占位图。** 所以「文件哈希没变」不能证明
  「没重跑」——本实验用**接口调用计数**来证明，这一点在真实厂商下也同样成立。
- **审核意见要结构化。** 存一段自由文本，下一次自动化用不上；存成 `verdict` + `tags` + `comment`，
  才能拿「连续两次 face-inconsistent 就别再自动重试」这样的规则去用它（D11 会接着用这份记录）。
