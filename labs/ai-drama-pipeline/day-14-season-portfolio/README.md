# D14 实验：一次运行产出一季五集的批量脚本与一份作品集材料

> 目标：把前十三天攒下来的东西一次性用掉——用同一份世界观档案驱动五集连续生成，用五条可判定的检查确认人物与画风没有跨集漂移，出一份带耗时 / 花费 / 失败率 / 人工介入次数的整季账单，最后自动生成一段演示片花、一张架构图和一份能直接放进简历的说明文档。

## 你会学到

- 用世界观档案驱动五集连续生成，检查人物与风格是否跨集一致
- 记录整季运行的耗时、花费、失败与人工介入次数
- 剪一段演示视频并画一张架构图，写进作品集说明文档
- 按三个技术故事的结构写出你的项目讲述稿
- 对着面试追问清单自答一遍，标出还答不上来的地方

## 目录

- `starter/`：挖了 4 个练习的起始代码，`MOCK=1` 下可以直接跑
- `solution/`：参考答案
- `src/providers/`、`src/ffmpeg.ts`、`src/run.ts`、`src/dag.ts`：**来自 D1，本天不改**（每个 lab 独立，不跨 lab import）
- `src/world.ts`：世界观档案、五集计划、提示词拼装（跨集一致性的唯一事实来源）
- `src/consistency.ts`：五条跨集一致性检查
- `src/ledger.ts`：整季账单与花费估算
- `src/portfolio.ts`：演示片花、架构图、说明文档模板

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env  # 填 MINIMAX_API_KEY；没有 key 先用 MOCK=1
MOCK=1 pnpm start                    # 离线模拟，五集一次跑完
INJECT=taskfail MOCK=1 pnpm start    # 注入一次视频任务失败，看失败率动起来
WORK_DIR=~/drama-out pnpm start                           # 真实厂商（产物写仓库外：花过钱的素材别放临时目录）
```

### 故障注入：`INJECT`

本课所有「人为制造一次失败」的地方都用同一个环境变量 `INJECT`，值是逗号分隔的场景名。
本天只支持一个：`taskfail`，让 E3 的第二镜视频第一次生成失败、退避后重试成功。
不注入时整季失败率是 0.0%，账单照样打印，只是失败那一列全是 0。

> 说明：`starter/` 与 `solution/` 都不属于仓库根 pnpm workspace（根 `pnpm-workspace.yaml` 只包含
> `apps/*`），`pnpm install` 时要加 `--ignore-workspace`。

跑完之后，作品集材料在 `work/runs/<runId>/output/portfolio/` 下：`demo.mp4`（演示片花）、
`architecture.mmd`（架构图源码）、`README.md`（说明文档，数字已经按本次运行填好）。
把这三样连同一集成片放进仓库或简历附件，就是一份别人三分钟能看懂的作品集。

### 金额同样是估算，而且三档单价可信度不同

`MOCK=1` 下 provider 返回的 `costCny` 恒为 0，账单里的钱由用量乘 `src/ledger.ts` 里的单价算出。

- **图像 ¥0.025 / 张**：官方按量付费页直接标价，可以当真。
- **视频按秒**：付费页给的是几个清晰度档位的按秒单价，而本课用的视频接口在官方走**视频点数**扣减、
  没有公开按秒单价，两套口径不通用——所以代码里那个每秒常量是**台账演示用的折算值**，
  不挂到任何具体模型 id 上。
- **语音按字符**：官方只公开资源包价，这是折算值（约每万字符三元多），不是官方标价。

这三句话要原样写进作品集文档，别让读的人误以为你贴了一张真实账单。

## 验收标准

1. `MOCK=1 pnpm start` 一次跑出五集，`output/` 下有 `episode-1.mp4` 到 `episode-5.mp4`
2. 跨集一致性检查五项全绿；把 `world.ts` 里任意一个角色的 `appearance` 改一个字，「角色外貌描述逐字来自档案」不会红，但把某一集 `hook` 改掉，「集间钩子首尾相接」立刻变红
3. 整季账单打印出每集的耗时、图像张数、视频秒数、语音字数、调用次数、失败次数、人工介入次数与估算花费；加上 `INJECT=taskfail` 重跑，合计行的失败率从 0.0% 变成 3.2%
4. `output/portfolio/demo.mp4` 由五集各抽第一镜流复制拼成，日志里看不到 `libx264`
5. `output/portfolio/README.md` 里的数字与本次运行的账单一致，三个技术故事的骨架已经写好

## 常见坑

1. **靠提示词写得像来保跨集一致。** 只要提示词是一集一集手写的，第三集就一定会漂。正确形态是「提示词只能从档案里拼出来」，人物外貌逐字取自 `cast`，风格词逐条附加——这样漂不了。
2. **一致性检查去看画面。** 画面好不好是质检的事（D11）。这一天查的是输入有没有漂：角色是不是档案里的、音色有没有换、外貌片段是不是逐字、风格词有没有丢、钩子有没有断。输入不漂，输出才有可能不漂。
3. **账单只记成功的调用。** 失败与重试也占了时间和配额，不记进去，你算出来的"单集成本"会比真实值低一截，容量规划全错。
4. **拼接成片时重新编码。** 同一套编码参数拼接用 `-c copy` 就够了；重压一遍既慢又掉画质，而且这一步在一季五集里要跑六次（五集加一条片花）。
5. **作品集只放代码仓库链接。** 没人会为了看懂你的项目去读源码。演示片花、架构图、说明文档三样各对应一类读者，缺一样这个项目在别人眼里就只是"跑了个脚本"。
