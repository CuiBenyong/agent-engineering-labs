# D5 实验：skill 运行时加载器

> 目标：把三阶段渐进式加载真的写出来——扫描目录发现 skill、宽松解析 frontmatter、把名字与描述拼成目录注入系统提示、激活时才读入正文。自己实现一遍之后，前四天每一条建议对应运行时的哪一行代码，你都能指出来。

## 你会学到

- 扫描 skill 目录：只认含 `SKILL.md` 的文件夹，设深度上限，跳过不该进的目录
- 同名冲突按作用域优先级取舍，并留下一条「被遮蔽」的警告而不是静默丢弃
- 宽松解析：只有缺 description 才跳过，其余不合规范的一律只告警仍然加载
- 构建目录并算出它每一轮的固定开销；激活时只注入被选中那一个的正文，并去重

## 目录

```
fixtures/
├── project/.agents/skills/    项目级：commit-message、release-report（带 references）、
│                              broken-yaml（裸冒号）、no-description（该被跳过）、
│                              name-mismatch（名字与目录不符）、not-a-skill（没有 SKILL.md）
└── user/.agents/skills/       用户级：一个同名的 commit-message，用来演示遮蔽

src/
├── parse.ts     frontmatter 分离 + 宽松校验
├── scan.ts      目录遍历 + 同名冲突优先级
├── catalog.ts   目录构建 + token 估算
├── activate.ts  激活：包装标签、列出资源、去重、标记受压缩保护
├── select.ts    唯一的网络出口：把目录交给模型让它选一个
└── index.ts     把三阶段串起来跑一遍，末尾打印 8 项自检
```

- `starter/`：挖了 5 个练习点，`MOCK=1` 下可以直接跑，但自检基本全红
- `solution/`：完整实现，`MOCK=1` 下 8 项自检全绿

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env  # 填 ANTHROPIC_API_KEY；没有 key 先用 MOCK=1
MOCK=1 pnpm start     # 离线跑完三阶段并打印自检
pnpm start            # 「选哪个 skill」那一步换成真模型
```

`solution/` 在 `MOCK=1` 下的结尾长这样：

```text
  ✅ 扫到了至少 3 个 skill
  ✅ 缺 description 的被跳过
  ✅ name 与目录名不一致的只告警仍加载
  ✅ description 里有裸冒号的仍能加载
  ✅ 同名冲突时项目级胜出
  ✅ 只有被选中的两个进了上下文，其余没有
  ✅ 重复激活被去重
  ✅ 带附件的 skill 列出了资源但没有读它们
```

> **只有「选哪个 skill」走网络。** 扫描、解析、目录构建、激活在 `MOCK=1` 下全是真跑的：
> 往 `fixtures/` 里加一个 skill，输出立刻会变。离线模拟的那一步是朴素关键词匹配，
> **描述写得好不好，仍然要去掉 `MOCK=1` 用真模型验。**

## 验收标准

1. `MOCK=1` 下能跑通三阶段并打印 8 项自检，全部为 ✅。
2. 扫描能识别「含 `SKILL.md` 的目录才是 skill」，`not-a-skill` 那种只有 README 的目录不被计入。
3. 同名冲突时项目级胜出，且被遮蔽的那一个留下了一条带两个路径的警告，而不是被静默丢弃。
4. 解析对四类不合规范的输入分别处理正确：缺 description 跳过，名字不一致、名字不合规、描述超长都只告警仍加载。
5. 激活只把被选中的 skill 正文放进上下文，重复激活被去重，附带资源只列文件名不读内容。

## 常见坑

1. **扫描一路钻到底。** 没有深度上限、不跳过 `node_modules`，在一个真实项目里会扫上几万个目录。而且找到 `SKILL.md` 之后就该停——skill 不嵌套，继续往下钻只会把附件目录误判成 skill。
2. **同名冲突静默丢弃。** 用户改了项目里那份，结果生效的是用户级那份，他会以为自己的修改没保存。**必须留一条警告，而且要把两个路径都写出来**，那条日志是排查这类问题的第一现场。
3. **严格校验，不合规范就拒绝加载。** 规范对 `name` 卡得很死，但别人写的 skill 常常不合规。运行时该做的是宽松：只有缺 description 才跳过（缺了它这个 skill 永远不会被选中），其余记诊断仍然加载。
4. **把正文一起塞进目录。** 目录是阶段一的产物，每一轮都要重发，正文进去就等于取消了渐进式加载。目录里只放名字、描述、位置三样。
5. **重复激活不去重。** 模型可能在同一次会话里再次选中同一个 skill，同一段指令出现两遍会互相干扰，还会白花 token。
6. **激活出来的消息没有做压缩保护。** 长会话里它被压缩掉之后不会报错，模型只是悄悄退回没有这个 skill 的行为——这是最难查的一类问题。`activate.ts` 里那个 `protectedFromCompaction` 标记就是为它准备的。
