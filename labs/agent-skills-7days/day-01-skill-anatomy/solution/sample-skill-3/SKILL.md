## 工作流

1. 从堆栈里抽出：最内层的异常类型、抛出位置、以及第一处属于本项目的调用帧。
2. 按「现象 / 触发条件 / 影响面 / 下一步」四栏填写，任何一栏信息不足就写「待补」并列出需要哪份日志。
3. 不要在「原因」一栏写猜测。没有证据的因果关系是复盘里最贵的错误。

## 坑

- 最外层异常通常是包装过的，真正有信息量的是最内层那个。
- 影响面要写数量级而不是形容词：「约 200 个请求」比「少量请求」有用得多。
