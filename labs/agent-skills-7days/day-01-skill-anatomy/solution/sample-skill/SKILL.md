description: 把一份接口变更说明整理成发布公告。当用户要写发布说明、changelog、版本公告，或者说「这次改了什么，帮我发出去」时使用；只负责整理已有的变更条目，不负责判断某个变更该不该发布。
---

## 工作流

1. 读取用户给的变更条目，按「破坏性变更 / 新增 / 修复」三类分桶。
2. 每一类里按影响面从大到小排序，影响面相同的按接口路径字典序排。
3. 套用下面的模板输出，三类都为空的类目整段省略，不要留一个空标题。

## 输出模板

```markdown
# vX.Y.Z

## 破坏性变更

- 一句话说清改了什么，以及调用方要改哪一行

## 新增

- 一句话说清能力，不写实现细节

## 修复

- 一句话说清现象，不写根因
```

## 坑

- 版本号不要自己猜。用户没给就直接问，猜错一个版本号比晚发半小时贵得多。
- 「性能优化」不是一类，它要么归新增要么归修复，看用户实际感知得到什么。
- 破坏性变更这一栏为空时要显式跟用户确认一次，多数情况下是漏了，不是真的没有。

## 引用

字段与状态码的完整对照见 `references/FIELDS.md`，**只在变更条目里出现了字段名或状态码时才读它**。
