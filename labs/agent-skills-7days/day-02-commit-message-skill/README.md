# D2 实验：一个「按团队规范写提交信息」的 skill

> 目标：写出你的第一个 skill，并且让它真的被触发——你说一句自然的话，客户端自己把它翻开，按你定的模板输出提交信息。今天的产出是一个 skill 目录加一份触发验证记录，不是程序。

## 你会学到

- 把一件重复纠正过的事收敛成一个 skill 的边界，并把「不管什么」写进 description
- 按祈使句、多种说法、口语句、边界句四段结构写出一版能触发的 description
- 把正文分成工作流、输出模板、坑三段，并用「不写它模型会不会做错」筛掉废话
- 把 skill 装进客户端并用三正一负四句话验证它的触发面

## 目录

- `starter/commit-message/SKILL.md`：挖了 4 个练习点的骨架，`> TODO 练习 N：` 是待填处
- `starter/trigger-log.md`：触发验证记录表，待填处是 `> TODO：`
- `solution/commit-message/SKILL.md`：填好的 skill
- `solution/trigger-log.md`：填好的验证记录，**故意保留了失败的那一轮**

## 怎么跑

这一天没有代码，所以**不需要** `pnpm install`、不需要 `MOCK=1`、也没有自检脚本。

1. 先把你团队的提交规范找出来。没有成文规范就把最近二十条提交拉出来看实际长什么样：

   ```bash
   git log --oneline -20
   ```

2. 通读 `solution/commit-message/SKILL.md`，先只看 frontmatter 猜它什么时候会被触发，再往下读正文验证。
3. 回到 `starter/commit-message/SKILL.md`，把 4 个 `> TODO 练习` 逐个换成你自己的内容。
4. 把整个 `commit-message/` 目录复制到客户端的 skill 目录，项目级或用户级都行：

   ```bash
   mkdir -p .agents/skills && cp -r starter/commit-message .agents/skills/
   ```

5. 先确认客户端的 skill 列表里能看到它（多数客户端有一个列出可用 skill 的命令），**看不到就先查扫描，别急着改描述**。
6. 用三句说法各不相同的话各触发一次，再用一句形似但不该触发的话验证边界，把四轮都记进 `starter/trigger-log.md`。
7. 数出三个数字填进记录表：

   ```bash
   wc -l starter/commit-message/SKILL.md
   ```

## 验收标准

1. `SKILL.md` 的 frontmatter 通过校验：name 符合五条命名规则且等于父目录名，description 在 1024 字符以内且不含未加引号的裸冒号。
2. description 里能逐条指出祈使句、用户意图、口语说法、边界四个部分各是哪一段。
3. 正文含工作流、输出模板、坑三段；坑那一段的每一条都能回答「不写它模型会不会做错」，答不出的已经删掉。
4. skill 装进客户端后，用三句说法各不相同的话各触发一次，三次都成功；并且用一句形似但不该触发的话验证它没有被误触发。
5. 触发验证记录里写清了每次用的原话、是否触发、以及没触发时你改了描述的哪一处。

## 常见坑

1. **列表里根本没有它，你却在改描述。** 排查顺序是固定的：先看客户端有没有扫到（`SKILL.md` 文件名大小写、目录名与 `name` 是否一致），再看 frontmatter 能不能解析，最后才轮到描述。顺序搞反，你会对着一行完全无辜的描述改一小时。
2. **description 里有裸冒号。** 写 `description: 当用户说：帮我提交时使用`，中间那个冒号会让 YAML 解析器判成非法。有的客户端兜底修复，有的直接跳过这个 skill。**值里要用冒号就整段加引号。**
3. **三句测试话其实是同一种说法。** 「写提交信息」「生成 commit message」「帮我写 commit」这三句只是同义替换，测的是同一个触发面。真正有用的第三句是完全不含专业词的口语，比如「这几个文件我要提交了」——描述的盲区几乎总在这一类上。
4. **近似负例挑得太远。** 「今天天气怎么样」当然不会触发，它什么也没测出来。有效的负例必须共享关键词而目标动词不同，比如「这次改动该不该现在提交」。
5. **坑那一段写成了正确的废话。** 「注意提交信息要清晰」不写模型也知道。真正的坑长这样：「类型只有六个，`perf` 和 `style` 在我们这儿分别归 `refactor` 和 `chore`」。
