# D4 实验：带脚本的文档处理 skill

> 目标：做出一个真正带 `scripts/` 的 skill——分析模板拿到真值、校验取值计划、填充输出文档三步各一个脚本，并让校验报出的错误具体到模型能自己改对。

## 你会学到

- 把「先规划、再校验、后执行」落成三个各司其职的脚本
- 写出可自纠的错误信息：哪一项错了、期望什么、实际是什么、可用值有哪些
- 用退出码区分业务失败与用法错误，把数据与诊断分流到标准输出与标准错误
- 让填充脚本在留有未填占位符时失败，而不是写出一份看起来完整的半成品

## 目录

```
skill/release-report/
├── SKILL.md              技能本体：工作流清单 + 坑 + 可用脚本
├── assets/template.md    发布报告模板，占位符形如 {{name:string}}，问号结尾表示可选
└── scripts/
    ├── cli.ts            三个脚本的统一命令行入口
    ├── analyze.ts        模板 → 字段清单（真值）
    ├── validate.ts       字段清单 + 取值计划 → 错误列表
    └── fill.ts           模板 + 取值计划 → 报告

fixtures/
├── values.bad.json       故意写错的计划：类型错两处、缺一个必填、多一个不存在的字段
└── values.good.json      修正后的计划

src/
├── index.ts              演示驱动：把五步走一遍并逐项打印 ✅ 或 ❌
└── summary.ts            整条流水线唯一的网络出口，MOCK=1 在这里打桩
```

- `starter/`：挖了 4 个练习点，`MOCK=1` 下可以直接跑，但会有三步是 ❌
- `solution/`：完整实现，`MOCK=1` 下全部 ✅

## 怎么跑

```bash
cd starter            # 或 solution
pnpm install --ignore-workspace
cp .env.example .env  # 填 ANTHROPIC_API_KEY；没有 key 先用 MOCK=1
MOCK=1 pnpm start     # 离线跑完五步 + 一个反面演示
pnpm start            # 摘要那一步换成真模型
```

三个脚本也可以单独跑，这正是 Agent 会敲的命令：

```bash
pnpm analyze skill/release-report/assets/template.md
pnpm validate tmp/fields.json fixtures/values.bad.json   # 退出码 1
pnpm fill skill/release-report/assets/template.md tmp/values.good.json
```

`starter/` 原样跑起来，第 1 步、第 3 步与最后的反面演示都是 ❌。做完四个练习之后，`solution/` 的输出末尾会打印「全部通过」。

> **只有摘要那一步走网络。** 分析、校验、填充在 `MOCK=1` 下是真跑的，不是假装跑——
> 改一个输入，输出一定跟着变。

## 验收标准

1. `MOCK=1` 下能跑通全流程，输出里能看到分析、生成摘要、校验失败、修正后校验通过、填充成功五步，最后一步反面演示被正确拒绝。
2. 分析脚本能从模板里抽出全部字段的名字、类型与是否必填，模型不需要凭记忆猜字段名。
3. 校验脚本能报出三类错误：必填字段缺失、类型不符、模板里没有的未知字段；未知字段那条要列出可用字段。
4. 填充脚本在还剩未填的必填占位符时以非零退出码失败，并列出是哪几个，而不是写出一份带占位符的文档。
5. `SKILL.md` 的工作流写成带复选框的清单，校验那一步单独成步且写明失败后要回到上一步重来。

## 常见坑

1. **错误信息写成「校验不通过」。** 这一条浪费一整轮：模型不知道哪错了，只能重猜。正确写法把四样东西给全——哪一项、期望什么、实际是什么、可用值有哪些。`solution` 里那条「模板里没有字段 signature_date。可用字段：……」就是标准形态。
2. **校验和填充写进同一个脚本。** 混在一起之后，模型没法在「计划」和「执行」之间停下来自我修正，而且一旦边填边校验，出错时文件已经写了一半。**文件系统没有事务，半成品文档比完全没写更麻烦——它看起来是完整的。**
3. **填充脚本不做自检。** 少填一个占位符就写出一份带着两对花括号的文档，那份文件会被当成填好的直接发出去。宁可以非零退出码失败。
4. **分析这一步被跳过，字段名靠猜。** 模板里叫 `endpointCount`，模型写成 `endpoint_count`，校验会报「模板里没有这个字段」——但如果连分析都没跑，你连这个报错都拿不到。**真值必须从模板里抽，不能从记忆里取。**
5. **类型当成字符串糊过去。** 接口数写成「七个」、破坏性变更写成「有」，是这个模板上最常见的两处错误。这不是脚本挑剔，是因为下游会拿这两个值做统计和判断。
