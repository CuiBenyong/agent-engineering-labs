# D7 实验：团队规范 skill 包与作品集条目

> 目标：把七天学的东西合成一次完整交付——拿一份**真实的**团队规范文档，按触发场景拆成三个 skill，交给干净的子代理跑一组带断言的对照评估，最后压成一条经得起追问的作品集条目。**这一天交付的是一句能被追问的结论，不是三份 SKILL.md。**

## 你会学到

- 按触发场景聚类而不是按章节切，把一份长文档拆成边界互斥的三个 skill
- 设计正例、边界例、负例三类用例，写出可判定的断言
- 用两份只差一行的子代理定义做干净对照，把「更好」变成一个通过率差值
- 把交付写成一条带测量条件、说得出「放弃了什么」的作品集条目

## 目录

- `starter/`：四份挖空的模板，骨架与提示问句都写好了，待填处是 `> TODO：` 引用块
- `solution/`：填好的示范样例，用的是一份 31 页工程手册拆出来的三个 skill

两个目录里的文件名一一对应：

| 文件                 | 干什么用                                       |
| -------------------- | ---------------------------------------------- |
| `split-table.md`     | 三步拆分：只记场景、按时刻聚类、写边界并查互斥 |
| `eval-cases.md`      | 15 条用例与断言，正例、边界例、负例三类        |
| `eval-result.md`     | 两组定义、测量条件、通过率与失败明细           |
| `portfolio-entry.md` | 中英各一条作品集条目，加四组追问准备与诚信自检 |

**填的顺序是固定的**：`split-table.md` → `eval-cases.md` → `eval-result.md` → `portfolio-entry.md`。边界没定清楚就去写用例，你会发现断言无从下笔。

## 怎么用

这一天没有需要安装的代码，所以**不需要** `pnpm install`、不需要 `MOCK=1`。正文里那段评分脚本可以直接拿去算通过率，也可以手算——15 条用例手算完全来得及。

1. 通读 `solution/` 的四份样例，重点看两处：`split-table.md` 里聚类结果怎么**不和章节重合**，`eval-cases.md` 里断言怎么做到「只查事实、不查好坏」。
2. 找一份**真实存在**的规范文档。你团队的工程手册、某个开源项目的贡献指南都行，**不要编一份出来**，编的文档拆不出真实的触发场景。
3. 回到 `starter/`，按固定顺序把每个 `> TODO：` 换成你自己的内容。
4. 建两份子代理定义，并排 diff 一遍确认只差一行，然后同一批用例各跑一遍。
5. 最后对着「验收标准」逐条自检。

## 验收标准

1. 拆分表里三个 skill 各写清了触发场景与「不管什么」，并注明来自源文档哪几段；**聚类结果与文档章节明显不重合**。
2. 用例不少于 12 条，正例、边界例、负例都有；每条 2 到 4 条断言，每条断言只查一件事且可判定（查事实，不查好坏）。
3. 两份子代理定义只差预加载 skill 那一行，其它逐字相同，且两组跑的是同一批用例；`eval-result.md` 里写明了 diff 过。
4. 结论给出了两边通过率与差值，失败明细逐条列出（用例编号加断言编号），人工判定的条数明确标出。
5. 作品集条目里每个数字都注明了测量条件，写清了「放弃了什么」与「为什么不直接写进系统提示」，并且主动写出了样本量的局限。

## 常见坑

1. **在调试过的会话里试 skill。** 那个上下文里散落着你手打的规范片段和你纠正过的措辞，模型产出得好是因为**你自己把答案说了一遍**。这是评估 skill 时最常见的自欺，必须用干净的子代理。
2. **两组不止差一行。** 换了模型、多了一个工具、提示词改了半句，你的数字就说不清是谁的功劳。跑之前并排 diff，这一步花两分钟，能省掉整个实验重做。
3. **没有负例。** 少了它你测不出触发面有没有过宽，而过宽是 skill 最常见的坏法——一个什么都抢的 skill 在纯正例集上也能拿满分。
4. **断言查的是好坏不是事实。** 「写得清楚」判不了，「首行不超过 50 字符」「类型取自那六个值之一」才判得了。判不了的老实标人工判定，**硬凑只会得到一个假绿**。
5. **按章节切 skill。** 章节结构服务人的阅读顺序，skill 边界服务触发时刻，两者几乎从不重合。如果你的拆分表跟文档目录一一对应，退回第一步重来。
6. **把没跑过的数字写进作品集。** 「效率提升 50%」追问两句就穿帮，而且作废的不只是这一条，是你其余全部的真数字。宁可写「15 条用例、同一天跑的两组、53% 对 87%、其中 2 条人工判定」。
