# D1 实验：一份自用的 Claude 提示词模板集

> 目标：把「system prompt、XML 标签、先思考再回答、结构化输出」四个 Claude 特有的习惯，各写成一份带空位的 Markdown 模板，并用示例任务填一遍。今天的产出是文档，不是程序——这套模板后面四天每天都会用到。

## 你会学到

- 写一份 system prompt 模板：角色、边界、输出风格三段
- 写一份长输入模板：用 XML 标签分装材料、指令与示例
- 写一份先思考再回答的模板：分析段与答案段分开
- 写一份结构化输出模板：附一个最小 JSON Schema
- 用今天的示例任务（给 TODO API 补校验和测试）把四份模板各填一遍

## 目录

- `starter/`：四份挖空的模板，骨架与提示问句都写好了，待填处是 `> TODO：` 引用块
- `solution/`：填好的示范，用的是本课贯穿的示例任务「给 Express / FastAPI 的 TODO API 补上输入校验和对应的单元测试」

两个目录里的文件名一一对应：

| 文件               | 对应习惯                     |
| ------------------ | ---------------------------- |
| `system-prompt.md` | 名片：角色、边界、输出风格   |
| `long-input.md`    | 文件袋：XML 标签分装长输入   |
| `think-first.md`   | 先想再说：分析段与答案段分开 |
| `structured.md`    | 填表：JSON Schema 结构化输出 |

## 怎么用

这是**文档型实验**：不需要 `pnpm install`、不需要 `MOCK=1`、没有自检脚本。

1. 先通读 `solution/` 四份，看清「一个习惯落成一份模板」长什么样。
2. 回到 `starter/`，把每个 `> TODO：` 换成**你自己项目**的内容。`solution/` 是参照物，不是答案——将来这套模板装的是你的项目，不是课程里的 TODO API。
3. 把填好的四份在任意 Claude 客户端或 API Playground 里各跑一次，观察输出是否分段、是否符合 schema，不满意的地方改回模板。
4. 对着下面的验收标准逐条自检。

## 验收标准

1. `system-prompt.md` 有角色、边界、输出风格三段，全文不含日期、用户名等会变的信息，不超过 300 字。
2. `long-input.md` 用至少三个成对的顶层标签分装材料、指令、示例，指令在材料之后。
3. `think-first.md` 明确写出分析段与答案段各用什么标签，并说明程序只取哪一段。
4. `structured.md` 附一个最小 JSON Schema，字段不少于三个，且没有在提示词正文里重复描述格式。
5. 四份模板都用示例任务填过一遍，填好的版本放在同一文件的「示例」一节。

## 常见坑

1. **名片上写了会变的东西。** 「今天是 2026-09-06」「当前用户是张三」放进 system 开头，D2 讲的 prompt caching 前缀每次都变，缓存一次都命中不了。会变的信息放 user 消息。
2. **指令放在材料前面。** 材料一长，模型读到最后已经「忘了」开头要它做什么。材料在前、指令在后。
3. **schema 写了两遍。** 既传了 `output_config.format`，又在提示词里描述「请按以下 JSON 返回……」。两处只要不一致，模型就会被拉扯。schema 只写一处。
4. **把每句话都包进标签。** 三到六个顶层标签是常态，二十个标签只会让模型和你自己都看不清结构。
