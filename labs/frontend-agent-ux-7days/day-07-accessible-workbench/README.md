## 这一天最反直觉的一件事

**把实时区域指向流式渲染的那个元素是错的**，而那恰恰是最多人的第一反应。

两个陷阱：

| 做法                               | 后果                                               |
| ---------------------------------- | -------------------------------------------------- |
| `aria-atomic="true"` 指向流式元素  | 每来一个增量就重念整段，用户听到不断从头开始的噪音 |
| `aria-atomic="false"` 指向流式元素 | 高频 DOM 变化被屏幕阅读器整个跳过，什么都听不到    |

而且 NVDA、JAWS、VoiceOver 三家对高频变化的处理各不相同，
所以「在我的机器上能用」在这里特别不可靠。

**正确做法：流式期间静默，按句子完成时分段播报。**
视觉用户逐字看到内容，屏幕阅读器用户按句子听到内容，节奏相当，两边都不被淹没。

## 本机实测结果（Playwright 驱动真实 Chromium）

```
实时区域：加载时存在且为空 ✓
计算样式：position:absolute, width:1px（不是 display:none）✓
aria 属性：aria-live=polite, aria-atomic=false, role=status ✓
第一个 Tab：落在「跳到主内容」跳转链接上 ✓
播报节奏：整次运行只触发 2 次实时区域变化，内容是两个完整句子
性能预算：首字延迟 879 / 1000 ms，每秒更新 4 / 70 次，DOM 节点 108 / 5000
```

对照一下：如果退化成每次都播报全文，同一段文本会触发 **37 次**播报，
每次都从头开始念。

## 三个练习点

1. **`announcer.ts`：`flush`。** 按句子分段，只播报新增部分。
2. **`live-region.tsx`：实时区域的三个属性。** 视觉隐藏方式、live 级别、atomic 取值。
3. **`chat.tsx`：新消息开始时播报器要做什么。** 这个 bug 只有在浏览器里才看得出来。

## 验收标准

1. 实时区域在页面加载时存在且为空
2. 视觉隐藏用的是 `position:absolute` 一类手法，不是 `display:none`
3. 一次运行里实时区域的变化次数**远少于**增量数，且每次都是完整句子
4. 第一个 Tab 落在跳转链接上，所有按钮都能用键盘操作
5. 性能预算面板显示实测值，超标项标红
6. `pnpm typecheck && pnpm selftest` 退出码为 0

## 一个只有浏览器实测才能发现的 bug

写这个 lab 时，逻辑层的自检全绿，但浏览器里听到的第二句是
「**速**高于行业均值。」——开头被吞掉了。

原因是播报器按「一条消息」追踪已播报到哪个位置，而第二条消息开始时没有重置，
于是沿用了第一条的偏移量，把开头一截当成「已经念过」跳过了。

**逻辑层测试发现不了它**，因为单条消息的分段完全正确。是浏览器实测抓到的。
修完之后补了一条回归断言，并做了变异检验确认它会红。

这件事印证了这门课反复说的：**UI 课的很多东西只能肉眼验**，
`pnpm selftest` 绿了不等于做完了。上面那份手动验收清单不是走过场。

## 接真实模型后端

全课默认离线，因为这门课教的是「收到事件之后界面怎么办」。想接真模型的话，
要替换的只有**服务端路由**一个文件，前端一行都不用改——这正是对齐协议的好处。

改 `src/app/api/agent/route.ts`，把剧本换成真实模型调用：

1. 从环境变量读 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`（任何 OpenAI 兼容网关都行）
2. 用 `stream: true` 发起请求，把模型的 SSE 分片解析出来
3. 把分片翻译成本课的事件：文本增量转 `TEXT_MESSAGE_CONTENT`，
   `tool_calls` 转 `TOOL_CALL_*` 三段，推理内容转 `REASONING_MESSAGE_CONTENT`
4. 用 `encodeEvent()` 吐出去，格式与剧本完全一致

接上之后你会立刻发现几件被离线剧本的确定性掩盖掉的事：

- **首字延迟差一个数量级**。会先想很久的模型十几秒才开口，而剧本是 60ms。
  这时 D2 的流式渲染和 D7 的播报节奏都要重新调。
- **分片粒度完全不可控**。同一段话在不同模型上可能是 30 片也可能是 160 片，
  D2 的按帧合并从「优化」变成「必需」。
- **`tool_calls` 的分片 index 起点不可假设**。同一个模型两次运行可能给出 `0,1` 和 `1,2`，
  所以归并必须按 index 建字典而不是按数组下标。
- **模型会吐出不合法的 JSON**。D3 那个「参数 parse 失败也不要崩」的分支不是防御性编程，
  是真的会走到。

建议保留离线剧本不要删：它是你调试界面行为时唯一确定的参照物。
