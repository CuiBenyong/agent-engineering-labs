# D6 实验：会话控制与长任务

把前五天的零件组装成工作台：打断、续播、编辑重发、分支切换、
长任务进度、子 Agent 可视化。

## 跑起来

```bash
cd starter        # 或 solution
pnpm install --ignore-workspace
pnpm start        # http://localhost:3136
```

```bash
pnpm typecheck && pnpm selftest
```

## 这一天的三个核心

### 1. 打断停不住服务端

`AbortController.abort()` 关闭的是**前端这一侧**的连接。服务端那边的运行还在跑，
token 还在烧。真要停下来需要两件事一起做：

- `abort()` 让界面立刻响应
- 另发一个显式的取消请求，让服务端真的停

有个很常见的自相矛盾的 bug：取消请求复用了同一个已经 abort 的 signal，
于是它在发出前就被取消掉了。取消请求必须用新的（或者不带）signal。

### 2. 续播一定会重复，去重是前端的责任

服务端的重放边界不可能精确到字节，所以续播必然重发一些已收到的事件。

去重的口径是关键：**按标识和序号去重，绝不按内容去重**。

模型完全可能连续吐出两个一模一样的增量（两个空格、重复的标点）。
按内容去重会把合法的重复吃掉，表现是正文莫名其妙少字，而且极难复现。

### 3. 会话是树不是线

编辑重发和「换个说法再试」这两个需求，在线性历史里只能靠**丢掉后面的内容**实现。
用户改了三轮前的一句话，后面十几轮全没了——而他往往只是想对比两种问法。

树的模型下，编辑重发 = 在同一个父节点下新开一个分支，**旧分支完整保留**，
界面上用「2 / 3」加左右箭头切换。

## 四个练习点

1. **`session-tree.ts`：`branchFrom`。** 父节点原有的 children 不能丢。
2. **`resume.ts`：`dedupeKey` 的默认分支。** 增量类事件该不该有去重键？
3. **`resume.ts`：`ResumeTracker.accept`。** 有序号走序号，没序号退回标识。
4. **`resume.ts`：`stopRun`。** abort 之外还要做什么？

## 验收标准

1. 发送后可以「停止」，界面立刻停下且不显示红色报错（打断不是错误）
2. 停止后出现「续播」，点击能接着收完剩下的内容
3. 续播时重复到达的事件被去掉，正文不出现重复段落
4. 每一轮都能编辑重发，旧分支保留并可用左右箭头切换
5. 长任务的步骤逐个打勾，两个子 Agent 各自显示在自己的区域
6. `pnpm typecheck && pnpm selftest` 退出码为 0

## 手动验收清单

- [ ] 流式期间点「停止」：界面立刻停，**没有**红色报错（AbortError 不该当错误渲染）
- [ ] 控制台能看到 `[agent] 收到取消请求`，说明取消请求真的发出去了
- [ ] 点「续播」：内容接着往下走，**没有**重复的句子
- [ ] 编辑第一轮并重发：出现「1 / 2」，点左箭头能看回原来的问法
- [ ] 两个子 Agent 的文字各自出现在自己的卡片里，**没有串台**
- [ ] 进度条那一行显示的是「已完成的步骤」，而不是一个假的百分比

## 一处逐天叠加的债，以及怎么还的

`route.ts` 里原本是一条逐天追加的 if 链（D1 加一个分支、D3 加一个、D4 加一个……）。
到 D6 时出现了同一个 `inject` 取值被赋两次含义的 bug——`burst` 既指向工具剧本
又指向生成式剧本，后一个分支永远不可达。

而 TypeScript **只是在类型收窄时才顺带把它报出来**，如果取值是普通字符串就完全静默。

修法是改成一张表（`SCRIPTS` 映射），重复的键在语法层面就不可能存在。
这是「逐天叠加」这种写法的典型代价：每天单看都合理，攒到第六天就出问题。
